# 幂等安装器：写一个能反复跑、跑错也改不坏系统的部署脚本

## 技能定位

回答「安装/部署脚本该怎么写」：同一份脚本在一台**已经装好**的机器上再跑一遍，
必须既不报错、也不产生新副作用；想先看它打算干什么时，必须能**只看不改**。

适用于：把一批资产从源目录铺到目标目录、给服务装配置文件、打补丁、装扩展、建目录。
不适用于：一次性迁移脚本（跑完即弃）、需要逐步交互确认的向导、应用自身的版本化数据迁移
（那需要自己的状态表与版本号）。

> 核心判据：**脚本的每一次执行结果，只取决于目标系统的当前状态，而不取决于它被跑了几次。**

## 一、四条硬规矩

| # | 规矩 | 为什么 |
| :--- | :--- | :--- |
| 1 | `set -e -u -o pipefail` | 出错即停；引用未定义变量即停；管道中间段失败也算失败。少 `-u` 的脚本会把空变量当路径，静默改错地方 |
| 2 | 所有写操作只经**一个出口函数** | 出口函数里判 `--dry-run`，于是「只看不改」天然全覆盖，不靠人工记得逐个分支判断 |
| 3 | 判定「已一致」看**当前内容**（`cmp`），不看时间戳或标记文件 | 目标可能被人手改过、或同秒内被别的工具改写；标记文件与真实状态会漂移 |
| 4 | 不在这里启停服务、不碰凭据文件 | 安装脚本会被反复跑（含干跑式演练）；重启会打断别人，凭据覆盖会把真实密钥换成模板 |

## 二、可复制的骨架

```bash
#!/usr/bin/env bash
set -e -u -o pipefail

DRY_RUN=0
log()  { printf '  %s\n' "$*"; }
die()  { printf 'ERROR: %s\n' "$*" >&2; exit 1; }

for arg in "$@"; do
  case "$arg" in
    --dry-run) DRY_RUN=1 ;;
    -h|--help) printf '用法: %s [--dry-run]\n' "$0"; exit 0 ;;
    *) die "未知参数: $arg" ;;     # 静默忽略未知参数 = 有人以为传了隔离目录，实际没传
  esac
done

# 唯一写出口：--dry-run 只打印，不落盘
run() {
  if [ "$DRY_RUN" -eq 1 ]; then
    printf '  [dry-run] %s\n' "$*"
    return 0
  fi
  "$@"
}

# 逐文件铺：内容一致就不动它（保住 mtime，避免无谓的缓存失效/重载）
sync_file() {
  local src="$1" dst="$2"
  [ -f "$src" ] || die "源文件不存在: $src"
  if [ -f "$dst" ] && cmp -s "$src" "$dst"; then
    log "已一致，跳过: $dst"
    return 0
  fi
  run install -D -m 0644 "$src" "$dst"    # install -D 顺带建父目录
}

# 目录幂等：-p 重复跑不报错
ensure_dir() { run install -d -m 0755 "$1"; }

ensure_dir "${TARGET_DIR:?需要设置 TARGET_DIR}"
sync_file "$SRC/config.yaml.template" "$TARGET_DIR/config.yaml"

# 凭据文件：只判存在性，绝不复制、覆盖或打印内容
[ -e "$TARGET_DIR/env.example" ] || die "缺少 env.example，检查资产是否齐全"

if [ "$DRY_RUN" -eq 0 ]; then
  printf '\n下一步（人工执行）:\n  sudo systemctl restart <service-name>\n'
fi
```

## 三、常见坑与反例

1. **dry-run 里误改系统**：最常见的来源是「顺手在某个分支里直接写了 `cp`/`mkdir`」，
   绕过了出口函数。规矩：写操作只允许出现在 `run` 之后，代码 review 时 grep 一遍
   `cp|mv|rm|mkdir|install|ln` 确认没有裸调用。
2. **把服务重启塞进安装脚本**：安装脚本会被反复跑、还会被当演练干跑；重启会打断别人，
   而且重启失败会让整次安装看起来失败——其实文件都已经就位了。**打印人工步骤，让人决定何时重启。**
3. **用 `cp -r` 或带删除的目录同步覆盖整个目录**：会连带删掉目标目录里别人放的文件。
   改成逐文件 + 显式白名单。
4. **幂等判定用时间戳或 md5 命令**：`cmp -s` 直接就是内容相等、无外部依赖；各系统上
   摘要命令的名字与选项还不统一。`mkdir -p` / `ln -sfn` 这类自带幂等的写法优先。
5. **`-u` 下引用可能未设置的变量**：一律写 `${VAR:-默认}` 或 `${VAR:?缺它就退出}`，
   别让空变量变成 `/`。
6. **目标不存在时先比内容**：`cmp` 会报错退出（在 `set -e` 下直接终止），所以先 `[ -f "$dst" ]`。
7. **凭据文件**：永远不要 `install` 覆盖 `.env` 一类文件——真实密钥会被模板顶掉。
   只检查存在性，缺失时提示「从安全渠道获取」，不读内容、不打印内容。
8. **`set -x` 会打印参数**，参数里带敏感值时就是泄漏。别在脚本里常开 `-x`；
   调试时临时开、并在敏感处关掉。
9. **靠「跑过一次」的标记文件实现幂等**：标记存在但文件被人删了/改过，脚本会以为已装好。
   幂等判定永远看**当前内容**，不看历史痕迹。

## 四、自检清单

- [ ] `--dry-run` 真跑过，并用提交状态/文件时间戳快照对比，证明系统确实没被改？
- [ ] 在已装好的机器上连跑两次：第二次全部输出「跳过」，退出码 0？
- [ ] 所有写操作都经出口函数（grep 过 `cp|mv|rm|mkdir|install|ln`，没有裸调用）？
- [ ] 脚本里没有启停服务，只有打印出来的人工步骤？
- [ ] 凭据文件只判存在性，不复制、不覆盖、不打印内容？
- [ ] `set -e -u -o pipefail` 齐全，未知参数会报错退出而不是静默继续？
- [ ] 目标目录不存在 / 目标文件不存在 / 目标文件是符号链接 / 源文件缺失，四种情况都跑过？
