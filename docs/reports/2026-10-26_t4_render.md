## Final behavior

The existing render / screenshot / trim / CLI entry points remain available.
`screenshot(html_path, png_path, width, height)` now returns a manifest. Height
is the initial viewport, never a truncation cap. Chromium runs in an isolated
profile and blocks network requests while capturing. CDP waits for explicit
Mermaid completion, fonts and layout frames before measuring and capturing.

The first page is `<stem>.png`, followed by `<stem>.page-02.png`, etc. Each page
has a measured contiguous source range in `<stem>.render.json`; the last range
includes the footer. Page cuts avoid charts, tables, code and headings detached
from their following content. Oversized protected blocks may exceed the normal
page-height target rather than being cut in half.

The manifest includes full height, image dimensions, diagram counts, horizontal
overflow checks, minimum diagram label height, warnings and source Markdown
SHA-256. Extremely small diagram text or overflow fails capture instead of
silently delivering an unreadable layout.

PNG-only always renders current Markdown through temporary HTML. It does not
reuse stale HTML. Browser failure or invalid Mermaid is nonzero; existing old
PNG cannot establish success. Images are verified before atomic replacement.
The diagram fence parser is shared by conversion and counting and preserves
Mermaid examples nested inside longer ordinary code fences.

Browser discovery checks ARCH_DOC_BROWSER, supplied candidates, PATH and the
current user's local bin. No deployment username is embedded in the source.
Missing Mermaid cannot silently turn into a CDN script. The self-contained
renderer assets are inline; arbitrary externally linked source images are not
downloaded or archived by this implementation.

## Stable quality-check interface

```bash
python3 /absolute/tools/doc_browser.py --verify /absolute/doc.html --expected 2 --width 1100
```

Python: `inspect_document(html_path, width=1100, expected_diagrams=None)` returns
the same layout and diagram quality metrics used by screenshot capture. This is
the authoritative replacement for independent browser+grep checks.

Optional capture dependencies are websocket-client, Pillow and a local Chromium.
HTML-only remains available without browser capture; run the verification API
when claiming that diagrams have actually rendered.
