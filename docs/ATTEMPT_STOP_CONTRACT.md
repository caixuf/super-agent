# 执行停止与终态契约

状态：本地候选实现，未切换现场。更新：2026-11-03。

- Pool 是任务、attempt、启动许可、终态与 outbox 的唯一主账。
- `begin_execution` 是受信执行器的启动栅栏；claim 本身不授权执行。
- `attempt_supervisor` 只监管管理员配置的本地 runner 进程树。
- 依赖为 Worker/只读适配器 → Pool；Pool → 独立监管进程；核心不导入 IM。
- 监管器先启用 Linux subreaper、安装停止处理器，再发送 ready。
- 启动与 ready 等待不持有任务数据库事务；短事务复核暂停/取消并登记监管身份。
- Pool 提交 PID/启动身份/nonce 后发送 go；许可前 EOF 不启动 runner。
- 停止/Worker EOF/主进程退出后，监管器杀死并收养后代，直到 `waitpid` 返回 ECHILD。
- 停止回执绑定 job、attempt、token、nonce、监管器 PID 与启动身份；runner stdout 不充当停止证明。
- Pool 校验私有回执后才允许终结/恢复；取消请求、超时、空 token 扫描和 PID 消失均不能替代回执。
- 同步只读所有者必须先获许可；正常返回可确认回调结束，崩溃不自动重跑。
- 前台依据主账显示取消中；只有真实取消终态才显示已取消、触发终态交付。
- 监管器丢失且停止未证明时保留监管身份用于核验，前台显示停止尚未确认，而不是健康运行。
- 人审桥接只在主账接受操作后消费待处理记录；停止未确认时拒绝恢复，不标为已批准。
- 保留未知状态的代价是需要受信运维核查；不采用“超时强制成功收尾”的替代方案。

## 信任与故障范围

这是 Linux 本地进程生命周期监管，不是恶意代码沙箱。subreaper 可覆盖普通
双重 fork、`setsid`、清空环境变量；但不能防止同 UID 任意代码攻击监管器、
修改私有队列/回执、委托外部 daemon、远程作业或撤销已经发生的外部效果。
监管器被 SIGKILL、缺少/损坏/跨 attempt 回执时保持未知，不因锁释放而重放。
不得因此解除 `colleague_worker` 的可信 containment/readiness 门禁。

监管器持有 job lock，子 runner 不继承控制、停止回执或锁的 fd。停止确认超时后
Worker 可结束本地等待，但不得 SIGKILL 监管器然后冒充停止；仍活着的监管器保留锁。
进程处于不可中断内核等待时，不能保证取消立即完成。

## 旧记录与升级

迁移只添加 `execution_state` / `supervisor_nonce` 列，不更改旧任务状态、结果或 outbox。
没有新启动栅栏/回执的旧在途任务为未知：不补造证据、不自动重跑或发送取消终态。
升级需先排空/核查旧执行器，再在明确窗口切换所有 Worker 与观察者；不支持新旧
调度代码同时操作一个队列的滚动升级，旧执行器不会遵守新启动栅栏。
此文档和测试没有执行现场切换、服务重启、真实消息发送或生产任务重放。

## 验证

`tests/test_cancel_request_truth.py` 包含真实活进程、脱离进程组并清空环境的后代、
Worker 被杀、监管器被杀、停止回执字段篡改、启动超时后迟到执行器和暂停恢复栅栏。
`tests/test_pool_recovery.py` / watchdog 专项覆盖正常恢复及回调丢失；watchdog 正向
用例使用真实监管器回执，不再以假死 PID 充当停止证明。
只读测试使用离线模型/替身传输，不能替代真实服务、模型或 IM 验收。
