# 仓级棘轮门禁：让一条红线只许收紧，不许放松

## 技能定位

回答「怎么给仓库加一道能长期守住的自动约束」——禁止某类字面量、禁止新增的依赖方向、禁止某类文件进仓，
都属同一类问题。三个要点：门禁要**抓得到**（不是恒真断言）、**收得紧**（豁免必须显式且被钉死）、
**跑得早**（新建文件在提交前就已被覆盖）。不适用于一次性清理脚本、纯格式化工具、只提醒不拦人的巡检。

> 核心判据：**一条没人能偷偷放松、且能自证不是恒真的断言，才算门禁。**

## 一、先定顺序：门禁与存量，谁先

| 顺序 | 做法 | 适用 |
| :--- | :--- | :--- |
| A. 先清存量，再开门禁 | 违规清干净后再合入门禁，门禁第一天就是绿的 | 存量小、能一次清完 |
| B. 先开门禁 + 显式豁免存量 | 现有违规列进豁免清单，之后只许删不许加 | 存量多、一次清不完 |

**优先 A**：B 的豁免清单会变成第二个「允许污染的地方」，而清单越长时间越没人看。
非选 B 不可时，把「豁免项只能减少」也写成断言，并每清完一批就收紧一次钉死的长度，
否则 B 会停在初始豁免量上。选哪条、为什么，写进交付说明。

## 二、规则必须单一真相源

规则列表只能有一个定义处；其他任何地方（第二个测试文件、CI 脚本、文档）都**不许重抄**——
重抄的两份会在某次改动里漂移，而漂移的那天没人发现：门禁看起来还在，实际已被放松。
文档里也不要抄规则，写「规则见 `<path>`」即可。

```python
# 规则集唯一定义处（rules.py，或已有那个测试文件）
BANNED = ("<token-a>", "<token-b>")

# 其他文件按路径加载它，不要复制
import importlib.util
spec = importlib.util.spec_from_file_location("_rules", RULES_FILE)
mod = importlib.util.module_from_spec(spec); spec.loader.exec_module(mod)
BANNED = tuple(mod.BANNED)
```

## 三、匹配按「词」而不是按子串

```python
def pattern(token):
    if all(ord(c) < 128 for c in token):     # ASCII：加标识符边界，大小写不敏感
        return re.compile(r"(?<![A-Za-z0-9_])" + re.escape(token) + r"(?![A-Za-z0-9_])", re.I)
    return re.compile(re.escape(token))      # 非 ASCII：直接子串
```

不加边界 → 短词命中长词内部，门禁变噪声，很快被人加豁免绕过。不加大小写不敏感 → 换个写法就漏过。
非 ASCII 套 `\b` 更是错的：邻接行为不符合直觉。三条都会让门禁静默失效。

## 四、豁免清单：小、显式、被钉死

豁免清单是门禁最容易被攻破的地方。三条规矩：只允许「规则自身所在的那个文件」（它必须写出
被禁的词才能定义规则）；按**文件名**精确匹配，不用目录前缀/后缀通配（通配等于给整片目录开门）；
把长度钉死成断言 —— 任何人想加豁免都得先改它，改动就会出现在 diff 里被 review 看到：

```python
ALLOWLIST = {RULES_FILE.name}
assert len(ALLOWLIST) == 1, "豁免清单只许收缩；新增豁免必须走 review"
```

## 五、扫描范围：要扫「下一次提交会进版本库的文件」

只扫已跟踪文件会留一个窗口：**新建文件在被加入索引之前不受门禁约束**，
于是「先合进去、再补门禁」成为可行路径。

```bash
git ls-files --cached --others --exclude-standard   # 已跟踪 + 未跟踪但未被忽略
```

两条配套：git 不可用时**退化为遍历工作树**并排除 `.git` 目录，否则在无 git 环境里静默通过；
**二进制要跳过**（读首 8KB，含 NUL 字节即视为二进制）——随仓分发的编译产物不是我们写的文本。

## 六、门禁必须自检：证明自己不是恒真断言

一个**永远返回通过**的门禁比没有门禁更糟——它给人虚假的安全感。至少两条自检：

```python
def test_gate_covers_real_files():          # 确实扫到了一大片文件
    files = committable_files()
    assert len(files) > 10, "只扫到 %d 个文件，路径枚举大概率坏了" % len(files)
    assert any(f.suffix in (".py", ".md", ".sh") for f in files)

@pytest.mark.parametrize("token", BANNED)   # 每个词都真能抓到
def test_gate_detects_synthetic_violation(token):
    hits = list(violations(write_probe("line with %s inside" % token)))
    assert any(h[0].lower() == token.lower() for h in hits), "抓不到，门禁是假的"
```

「扫到一片文件」防路径枚举写错、扫了 0 个文件、于是永远绿；「违规样本必须被拦」防正则写错、
规则没生效。样本先写进**临时文件**再交给同一个扫描函数，这样读文件那一段也被验证到。

## 七、常见坑

1. **只扫包内源码**：违规从说明文档、部署脚本、配置模板里漏进来。要扫仓级全部会进版本库的文件。
2. **规则重抄**：另一个文件里又写一份清单 → 两处漂移。
3. **豁免用通配**：按目录前缀放行等于不再检查那片目录。
4. **只警告不失败**（`|| true`、只在日志里标红）→ 棘轮立刻失去效力。
5. **没有自检**：路径或正则一改，门禁静默失效，而它仍然是绿的。
6. **只挂在本地钩子**：钩子没装就没有约束；权威入口放 CI，本地跑同一份测试，钩子只是加速。

## 八、自检清单

- [ ] 规则集只有一个定义处，其他文件按路径加载而非重抄？文档只给路径不给副本？
- [ ] 匹配带标识符边界 + 大小写不敏感？非 ASCII 走独立路径？
- [ ] 豁免清单只有规则自身那个文件，且 `assert len(...) == N` 钉死？
- [ ] 扫描范围含「未跟踪但不被忽略」的文件？无 git 时退化遍历、二进制跳过？
- [ ] 有「扫到 >10 个文件」与「逐词违规样本必须被拦」两条自检？门禁本地一条命令可跑、**实测会红**？
