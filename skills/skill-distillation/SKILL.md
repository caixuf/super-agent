# 把一次经历固化成技能：门槛、脱敏、落盘、评审

## 技能定位

回答「这次踩的坑，值不值得写成技能；写在哪、写成什么样、谁来放行」。**不适用于**：一次性排障
（写进会话即可）、尚未验证的猜测（先验证再写）、纯业务约定（进业务叠加层，不进技术仓）。

> 核心判据：**写进技能的东西，必须是「别人照做也会踩」的坑，且有可复现的判据。**

## 一、门槛：三条同时满足才写

1. **会重复**：同类问题已出现 ≥2 次，或这类任务每周都会做；
2. **有判据**：能用一条命令/一次观察验证「修好了」（例如 `--check`、测试名、日志行）；
3. **非业务**：内容里没有具体企业/项目名、路径、凭据——业务部分改写成占位符。

只满足一条？→ 写进当次交付说明或记忆，不写技能。

## 二、结构（固定五段，短）

| 段 | 内容 | 常见错误 |
| :--- | :--- | :--- |
| 定位 | 回答什么问题、何时不适用 | 写成功能列表 |
| 判据 | 一句话核心判据 | 判据是「要小心」这类空话 |
| 步骤 | 按成本或风险排序 | 按工具顺序而不是判断顺序 |
| 反模式 | 见过的真实代价 | 列泛泛的「注意安全」 |
| 验收 | 可执行的检查 | 只写「确认无误」 |

## 三、脱敏：写之前过一遍

- 具体业务名 → `<business-domain>`；内部地址/端口 → 只在「部署方填写」一节出现；
- 凭据、token、内部 URL → **不出现**；需要的键名写进 `keys:` 列表供部署方填写；
- 真实主机名/用户名 → `host` / `<deploy-user>`。

写完后用仓里那道门禁自检（禁止字面量清单见对应测试文件），红的就改，不要加豁免。

## 四、落盘位置

| 内容 | 位置 |
| :--- | :--- |
| 跨环境可复用的流程 | 技术仓 `skills/<name>/SKILL.md` |
| 示范格式、不生产使用 | `skills/examples/<name>/` |
| 业务约定、企业专属步骤 | 业务叠加层技能源目录（部署时安装） |
| 一次性的结论 | 会话/交付说明，不落技能 |

## 五、评审：一个人看一遍就够

放行条件（缺一项不放）：

1. 判据可执行，且**当前状态下真的会失败**（证明不是恒真断言）；
2. 反模式里至少一条来自真实经历（写出代价，不写「可能」）；
3. 脱敏自检绿；
4. 技能名能看出「什么时候用」——不是 `misc`、`helper` 这类名字。

## 六、反模式

| 反模式 | 真实代价 |
| :--- | :--- |
| 把聊天过程抄进技能 | 技能变长、关键判据被淹没 |
| 一次经历直接晋升 | 技能库里堆满一次性动作，找东西靠翻 |
| 技能里写死本机路径 | 换机器照做即失败 |
| 只写「要检查」不写「怎么检查」 | 下一次仍然靠记忆判断 |
