# skills/

本目录是**技术仓**的技能目录：只放能跨环境迁移的流程，不放任何具体业务的约定。

| 路径 | 内容 | 何时安装 |
| :--- | :--- | :--- |
| `skills/<name>/` | 通用技能（与任何具体业务无关） | 默认安装 |
| `skills/examples/<name>/` | **示例技能**（示范格式与写法，不是生产流程） | **不安装** |
| 仓外业务技能源目录 | 业务技能（步骤里含具体企业/项目的约定） | 部署时由**业务叠加层**安装 |

## 一、边界：本仓只收「通用技能 + 示例技能」

一条技能属于本仓还是属于业务叠加层，判据只有一条：

> **把业务名词全部删掉以后，这条技能还剩下可执行的步骤吗？**
> - 剩得下 → 通用技能，可以进本仓。
> - 只剩一句「按业务的规矩来」→ 它是业务技能，留在业务叠加层。

因此本仓文件里不得出现具体企业、项目、行业的名词、路径或字段名。要举例时写占位符：
`<business-domain>`、`<service-name>`、`{{BUSINESS_OVERLAY}}`。

这条约束由**仓级棘轮门禁**自动守住（见 `tests/`）。它扫的是「下一次提交会进版本库的全部文件」
（已跟踪 + 未跟踪但未被忽略），所以新写的技能在提交之前就已经在约束之内，不留
「先合进去、再补门禁」的窗口。

## 二、示例技能：`skills/examples/`

`skills/examples/` 下的技能是**规范的可执行范本**，用来说明「一条合格的技能长什么样」。

- **不作为生产技能安装**：安装器在枚举技能时跳过 `examples/` 这一层，只装上一层的通用技能。
- **同样要满足本文件的格式与自检要求**（是示例，但不是豁免）。
- 每条示例只示范一件事，正文给可复制的骨架 + 反例，不写「当时那个项目是怎么做的」。

现含两条：

- `examples/idempotent-installer` —— 幂等安装/部署脚本的写法（反复跑不报错、干跑只看不改）。
- `examples/repo-gate-ratchet` —— 仓级棘轮门禁的写法（只许收紧、必须自检）。

## 三、新增技能的格式要求

一条技能 = 一个目录 + 一个 `SKILL.md`。**YAML frontmatter 至少含 `name` 与 `description`**：

```yaml
---
name: <skill-name>          # 与目录名一致，小写连字符
description: >-             # 触发词优先：第一句就要能被匹配到调用场景
  Use when <触发场景的一句话>. <加载后按什么方法做，一句话。>
version: 1.0.0
metadata:
  hermes:
    tags: [<检索标签>, ...]
    related_skills: [<相邻技能名>, ...]
---
```

要点：

- **`description` 是唯一会被检索到的东西**。第一句必须写「什么时候用」，形如
  `Use when ...` 或「当用户提到 X、Y、Z 时触发」；第二句才写行为。写成「关于某主题的说明」
  会永不匹配。
- **正文结构**：技能定位 → 步骤（可执行的命令/判据）→ 坑与反例 → 自检清单。
  步骤要能照做（给命令、给判据），不要停在形容词。
- **一条技能只解决一件事**。想写第二件事时拆成第二条，并在 `related_skills` 里互指。
- **细节放同目录的 `references/`**，正文只留判据与入口；不要把长材料堆进 `SKILL.md`。

## 四、新增技能的自检清单

- [ ] 目录名与 frontmatter 的 `name` 一致？
- [ ] frontmatter 可解析，且 `name` / `description` 都在？
- [ ] `description` 第一句写的是**触发场景**，不是主题说明？
- [ ] 正文给了可执行的命令或判据，不是纯原则陈述？
- [ ] 有「坑与反例」段，且每条坑都写了「表现 → 正确做法」？
- [ ] 有自检清单，且每一项都是**能当场验证**的判据？
- [ ] 全文过一遍仓级门禁（`python3 -m pytest tests/ -q`），确认不含业务名词？
- [ ] 若放在 `skills/<name>/`：把业务名词全删掉后，步骤仍然可执行？

`SKILL.md` 的 frontmatter 可在本地这样验：

```bash
python3 - "$1" <<'PY'
import sys, yaml
text = open(sys.argv[1], encoding="utf-8").read()
fm = yaml.safe_load(text.split("---\n", 2)[1])
assert {"name", "description"} <= set(fm), fm
print("OK", fm["name"])
PY
```
