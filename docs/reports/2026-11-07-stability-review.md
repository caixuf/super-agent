# Super Agent 稳定性与交付链审查

审查基线：`dbd9074c66b29b29057776c33e81526a7488aa68`；对象为 WSL 工作区 `super-agent`，日期 2026-11-07。本文描述工作区修改及其验证，不能作为线上发布或全部模块无缺陷的证明。

## 架构与审查边界

系统以 SQLite 持久队列、租约和 attempt 标识作为后台任务状态的依据；worker 调度执行，完成回执进入 outbox，再由传输层发往提交任务时保存的会话地址。`ColleaguePool` 在进程内复用角色槽位；`DirectCompletionTransport` 将文本和附件分解为持久化操作，记录 `sending`、`sent`、`unknown` 等状态。Hermes 插件与即时通讯适配器连接外部系统。记忆、代码图、安装与发布工具等模块在本轮未逐项完成深度审计。

本轮聚焦高风险的附件投递、attempt 栅栏及长期运行内存。运行实例与仓库是不同的发布目录；工作区修改不会自动进入已运行服务。

| 模块 | 权威状态与边界 | 故障处理要点 |
| --- | --- | --- |
| 持久队列与 worker | SQLite 记录 job、attempt、租约和 outbox；文件锁约束执行权 | 租约过期不等于旧进程已退出；终态写入必须核对 attempt |
| 同事池与调度器 | 进程内槽位只管理已接纳工作；结果以句柄或持久队列为准 | 排空需确认队列暂空；关闭时仍须等待或协作取消已接纳工作 |
| 记忆召回 CLI | 传入用户、agent、profile 和私有数据库目录 | 不可用与空结果分开报告；显式配置向量服务才能使用 CLI 向量排序 |
| 回执与附件 | outbox 决定待投递任务，direct 日志跟踪每次消息操作 | 只在有明确回执时确认；不确定操作先核实再处理，附件限制在所属 attempt |
| 宿主适配与进度消息 | 已解析的会话路由及宿主权限决定目的地 | 未验证的编辑适配器拒绝编辑；不可将拒绝解释为消息已更新 |
| 安装与发布 | 版本目录、描述文件、指向当前版本的链接和宿主配置共同构成部署 | 候选构建、服务切换和回滚分别验证；不要覆盖运行中版本目录 |

审查覆盖级别不同：上表是系统边界索引，具体已验证范围见下文；列入表格不代表该模块已完成全面安全或性能审计。

## 发现与处理

### 1. 摘要路径可触发越权附件读取（高）

此前摘要中的本地路径可被自动识别；Hermes 适配器还会把任意可读路径复制到 attempt 目录。模型输出或任务结果一旦包含其他文件路径，可能将不属于该任务的文件投递到群聊。单独的 CLI 附件发送绕过了既有的快照和发送日志。

修复后，仅允许自动识别所属 attempt 目录下的直接子文件，拒绝符号链接、隐藏文件和内部 `manifest.json` / `report.json`；显式附件仍由 `DirectCompletionTransport` 在发送前校验和快照。取消跨目录复制与旁路上传；attempt 目录本身也不能是符号链接，目录打开使用 `O_NOFOLLOW`。未知的文本路径只做有限脱敏，不成为上传授权。

正文改为“附件候选”，不再在实际发送前声称已经上传。所有附件作为持久化发送计划的一部分：收到确定回执后才可确认整体交付；不确定的发送被栅栏标记，不盲目重复。自动识别依赖现有路径匹配规则，并非通用敏感信息脱敏器；包含空格、非 ASCII 字符或其他根目录的路径需要另行评估。若 worker 需要交付目录外文件，应先由可信工作流复制到所属 attempt，再显式声明。

### 2. 槽位历史信息无限增长，提交栅栏不完整（中）

每个任务的完整结果和 epoch 曾永久保存在 `ColleaguePool` 内，长期进程内存随任务数和结果体积增长；提交仅核对 epoch，未核对 attempt token。现在不再保存无读取方的结果副本，活动任务释放槽位时清理对应索引；全局递增 epoch 避免回收后复用旧值，并同时核对 token。重复任务的旧槽位释放不会清理新 attempt 的记录。任务结果仍由返回句柄或持久队列承载。终态提交被拒绝时，句柄现在返回 `result_commit_rejected`，不会错误报告成功；持久队列保留原有租约恢复机制。

### 3. 默认召回受不可用向量服务阻塞（中）

组合记忆召回 CLI 以前在未配置向量端点时仍隐式调用本机向量服务；服务不可用时，多轮超时可能超过外层 12 秒期限，导致本可完成的关键词召回直接报错。现在 CLI 未显式配置端点时使用关键词召回；需要向量排序时使用 `--embed-url`（单独的记忆 CLI 也支持现有环境配置）。进程内和子进程两条路径保持一致。此行为调整仅适用于这两个 CLI，不改变记忆库其他调用方的默认配置。

### 4. 批量调度可能提前停止或超额持有租约（中）

批量排空原先在一批快速任务全部完成后直接退出，未再次检查持久队列；同时仅用空闲槽数估算容量，忽略已经提交但尚未进入槽位的任务。现在只在确认队列暂无可领任务且没有活动句柄时结束排空，并以已提交句柄与槽位共同约束认领；外部调用占满槽位时等待通知，避免空转。槽位获取失败时关闭认领锁，拒绝无效批大小；非映射任务载荷按现有容错约定处理。测试覆盖快速完成、待调度任务占额、外部占槽、锁释放及两种执行后端。

### 5. 进度消息的编辑意图在宿主通用发送链丢失（中）

对已解析会话使用宿主通用消息接口时，进度插件现在保留原有路由元数据并明确标记后续编辑意图。真实宿主的旧适配器缺少编辑安全判定所需接口时仍会拒绝编辑，不会为追求进度更新而冒险发出第二条消息。生命周期钩子直接调用宿主绑定上下文发送的路径及不同版本宿主的实际卡片行为仍需针对目标部署验收。

### 6. 候选构建的解释器和依赖准备（中）

候选构建以前在当前用户的工具目录不存在时，会尝试一个写死的其他用户目录。现已移除该路径：优先使用当前用户的受管解释器，否则查找当前 PATH 中的 `python3`。隔离构建还暴露了安装顺序问题：仅安装 Python 扩展时，宿主管理器不会选择工具集合，随后受管工具预检失败。现在先执行工具安装，成功后再同步扩展；任一步失败都停止构建并保留诊断。启动器生成和版本检查增加明确超时，依赖命令超时返回可识别的阻塞状态。具体候选版本仍需在目标环境验证依赖和启动。

### 7. 默认文本回执泄露宿主路径（中）

未启用附件上传时，原来的默认路径会把完整路径写入消息。现在摘要采用仅依赖路径文本的脱敏，附件显示文件名并注明未上传；重试不依赖文件是否还存在。路径匹配支持常见 Unicode 字母和数字、WSL 挂载路径以及指定形式的 Windows 用户目录，并对单独的用户目录隐藏用户名。Windows 路径只脱敏、不自动作为附件提取。此改动不上传文件，收件人需要通过授权的任务结果途径查看完整产物。

### 8. 任务卡片状态、归属与不确定更新（高）

任务卡片桥原本允许重复绑定覆盖记录、终态之后重新写入进度，也会在卡片中输出产物绝对路径。现在绑定和消息 ID 不可静默改写，查询及更新按 profile 限定；终态不可被不同终态或后续进度覆盖，卡片正文对路径作有限脱敏并只显示产物文件名。任务锁以固定数量的文件分片序列化跨进程更新，获取锁有超时；旧数据库会补充必要列。由于旧表没有发送结果记录，迁移时已有消息绑定被保守标记为未知，需要先核查，不能视为已送达或自动重发。

卡片更新前持久记录 `sending`，只有成功回执明确指向同一消息，或发送器明确证明未发送，才允许后续动作；超时、异常、缺失或不匹配的消息 ID，以及进程中断均保留不确定状态，不自动重发。明确未发送的同一终态允许按原内容重试；未知状态需要先在平台侧核实并由运维处理。状态写入成功不等于卡片已更新，调用方必须检查 `patch_result`。

宿主卡片发送器现在在更新前核对持久会话的频道、群和话题，并从平台读取消息，确认消息 ID、群、消息类型及机器人归属；随后通过宿主 SDK 的 PATCH 接口更新卡片，不调用可能将 JSON 当文字或另发新消息的通用编辑方法。平台请求发出后的异常保持未知；在事件循环自身线程调用时直接拒绝，避免阻塞网关。

### 9. 跨会话访问对无归属任务放行（高）

启用同配置跨会话查询时，原逻辑将缺少 profile 的来源也视为可访问；同一检查还用于取消操作。现在仅在持久来源明确属于当前 profile 时放行跨会话查询或取消，无归属和其他 profile 的任务继续拒绝；同一配置的正常跨会话查询保留。两个机器人均在隔离队列中验证了这些边界并向目标群回报。

### 10. 集群会话状态和远程调用结果（中）

本地会话状态文件损坏或不是映射时，旧逻辑会静默当成空状态并可能覆盖原始内容，造成会话亲和性丢失。现在拒绝执行并保留原文件；锁遇到非竞争性系统错误时直接报告。提交上下文设有长度上限。远程响应必须是布尔型 `ok` 且进程正常退出才可视为可信结果；提交或取消超时、异常退出及响应无效时标记结果未知且不自动重试，状态查询则允许重试。调用方需要先核实未知操作的远端状态；默认传输现限制标准输出 1 MiB、标准错误 128 KiB；异常过量会终止本地进程组并保守报告结果未知。远端操作可能仍在执行，需先核实；自定义 runner 不受此默认限制约束。

### 11. 状态命令输出缺乏事实依据（中）

`/boost` 原来将固定槽位数、角色拓扑和提速倍数展示为实时状态，实际并未检查对应运行节点或性能。现在只列出当前注册的角色和回执投递配置；实际节点、可用并发和性能明确标为未测量。该命令不执行健康检查，也不证明 worker 在线。两个机器人以隔离配置验证该行为并向目标群发送结果。

### 12. 网关停止时的回执调度（中）

网关事件循环已关闭或并发关闭导致回执协程无法调度时，原发送器可能遗留未关闭的协程，并让上层把确定未发送的操作记为未知。现在预先检查循环是否关闭；调度前失败时关闭协程并返回明确的未发送结果，使持久发送日志允许后续重试。已成功调度后的超时仍视为结果未知，不会盲目重发。原有网关循环线程内调用的拒绝保护保持不变。

### 13. 回执话题路由的完整性（中）

原发送器只在已保存话题不为空时检查话题，若原记录缺少话题而后续会话解析出话题，消息可能进入未经原记录绑定的话题。现在直达回执与卡片更新都要求保存的话题与解析结果一致；双方均无话题时仍可发送。旧任务若未保存话题而解析结果含话题，会被明确拒绝发送并保留待处理，须核实原始会话及路由后再按运维流程处理，不能直接假定目标话题正确。渠道和群的既有校验不变。

### 14. 附件快照的并发发布（中）

原实现先创建最终路径再写入文件；另一个投递进程可能读到半成品并误报冲突，进程中断也可能使最终路径永久指向不完整内容。现在先在相同目录写入并同步私有临时文件，再以硬链接原子发布最终路径并同步目录；并发竞争者验证已有文件的类型及字节后复用。正常异常路径会清理临时文件，但进程被强制终止或机器断电仍可能留下孤立的 `.snapshot-*` 文件，需要运维清理；没有进行断电测试。该方案依赖快照目录所在文件系统支持硬链接及目录同步。

### 15. 初始卡片创建的持久栅栏（中）

卡片桥新增初始创建状态：创建前以 SQLite FULL 同步持久记录 `sending`，只有获得有效消息 ID 才记为 `sent`；明确未发送可重试，异常、超时或中断保留未知状态，重启后不自动重发。并发同一任务由跨进程锁串行；已完成任务首次创建时使用当前终态生成卡片。旧数据库没有创建记录，因此没有消息 ID 的旧绑定保守标为未知，需要人工核实。已绑定消息的旧记录保持已创建。创建器必须正确区分确定未发送和可能已发出；人工关联消息 ID 前需核实平台归属。

宿主发送器已增加初始卡片创建接口：校验 profile、会话、群、话题、卡片格式和稳定 UUID 支持，再由宿主适配器发送；发出后的异常保持未知。两个机器人通过该接口在隔离进程完成真实群卡片创建、重复调用及同消息更新。默认关闭的 `task_lifecycle_cards_enabled` 已将派发、同事务建卡意图和后台消费者接通；完成先于建卡时从持久终态回执补更新。建卡与普通回执使用独立线程，关闭时停止后续建卡；已在途请求不能保证即时中止。执行进程启动后会尝试推送一次运行态，不推断百分比；状态只是队列观察，不是实时存活证明。并发消费者先持久领取该更新，明确未发送可重试；进程中断或结果不明则不盲目重发。隔离群测试使用宿主适配器、真实平台和后台轮询，会话解析使用替身；线上网关尚未升级。

### 16. 卡片投递健康告警（中）

卡片意图被停放、创建或更新结果未知时，后台线程会定期汇总未知、停放、长时间在途和积压的计数，并限频写入告警；日志不含任务正文或会话地址。更新开始时记录时间，避免把正常在途操作立即视为超时。队列统计按异常状态索引查询，并在同一只读事务内获得一致快照；终态卡片的未知和长时间在途状态还直接从桥接数据库统计，覆盖两份记录间中断窗口。桥接计数按 profile 汇总，不受切换时间过滤，跨队列可能重复，不应相加。告警是运营线索，不证明平台结果，也不自动解除未知状态。

### 17. 远端记忆召回的恢复见证（高）

远端召回服务处于失败状态：日志中较早出现模块导入失败，最后一次失败记录为恢复源不匹配；当前安装代码在隔离数据库、临时检查点及套接字下完成启动、健康握手和样例召回，不能代表生产数据已恢复。对生产数据库使用只读 SQLite 连接和 `query_only` 校验现有检查点：主体、路径、日志代际、结构版本、序列范围和该序列的锚点匹配，但源设备号与 inode 不匹配，现有恢复契约因此拒绝服务启动。上述匹配不能证明没有遗漏见证之后的历史，也不能证明数据库替换经过授权；不得删除或重新初始化检查点来绕过该保护。只读检查显示当前源库位于 ext4；在常见记忆目录限定深度内扫描 67 个文件，未找到检查点记录的旧设备与 inode，不能排除其他备份位置。应核实数据库迁移或恢复记录、备份与写入历史，确认来源及完整性后按受控恢复方案处理。

#### 一致性副本与备份搜索结果

在常见记忆目录及相关宿主目录限定深度搜索约 6.3 万个目录项，发现三份较早的小型候选备份；它们不具备当前恢复见证要求的日志结构，不能提供当前历史连续性证明。搜索范围有限，不能排除其他备份。

以只读源连接和 SQLite 在线备份创建私有临时副本，低 I/O 优先级执行检查：副本 `quick_check(1)` 返回正常，日志代际、见证序列范围和锚点匹配。该检查不能证明应用数据语义正确，也不能证明见证点之后没有丢失写入。副本 `schema_version` 为 1，而原库和见证为 37；副本的设备号和 inode 也必然不是原文件身份，不能直接拿原见证对副本作完整恢复验收。临时副本已删除，没有覆盖源库或原见证，也没有保留独立恢复备份。

#### 独立水位与事件队列核对

只读检查独立健康告警库中的 44 条事件，25 条包含可用水位，最高观察序列为 9632；当前见证及源库序列均为 9647。未发现高于当前源库的健康观察，但该告警库只记录部分健康事件，并非完整写入账本。

按检查点文件 mtime 到当前源库 ctime 的时间窗口，独立回合队列有 4 条事件标记完成；对应审计表没有可交叉核对的事实 ID，也没有对应审计行。完成回合并不必然写入记忆，文件时间也不证明数据库替换时间；两个数据库是分别只读取样，结果不能证明存在或不存在遗漏写入。保留原见证，继续依赖独立备份、迁移记录或其他写入证据确认连续性。

以下方案尚未执行为生产恢复；上面的临时副本检查只验证了隔离副本，没有保留备份。当前证据不能确认替换后的数据库包含见证点之后全部已提交数据，不能安全地重绑定见证。

1. 保持召回服务停止，盘点所有可能写入源库的进程和独立备份，确认迁移记录、备份生成时间及各份备份的来源。
2. 在访问受控、空间充足的隔离目录，以 SQLite 在线备份方式获得包含 WAL 状态的一致副本，并单独保全原检查点及其校验摘要；不得直接覆盖原库或见证。
3. 对独立备份、现有源库和外部审计证据比较代际、序列、锚点与最后已知写入水位，验证源库完整性和后续历史。单凭当前数据库自己记录的序列、锚点或文件时间不能证明未丢失尾部写入。
4. 仅在来源和完整性得到独立证据支持后，在副本上演练恢复、启动和召回，并保存对比结果；若证据不足，应先恢复或补齐缺失数据。
5. 按受控变更流程准备可回滚的生产恢复，保留原始数据库、WAL 和检查点；启动后核验服务健康、样例召回及持续写入，异常时停止并保留证据。不要以删除见证或直接使用 `--initialize` 代替恢复。

### 18. 只读恢复见证诊断

新增 `python3 -m agentcore.memory.recovery_checkpoint` 诊断入口，以显式数据目录、检查点和主体打开默认数据库的只读连接，比较主体绑定、源路径、设备、inode、日志代际、结构版本、序列范围及锚点；输出只包含布尔值或受限错误类型，不输出记忆正文、完整路径、设备号、inode、序列或令牌。此工具不会重建、修改或重绑定见证；即使所有检查通过，也不能证明见证点之后没有独立未记录的写入。命令及参数见 `docs/REDEPLOY.md`。

### 19. 矛盾发送回执的处理（中）

发送器若同时声明未发送并返回消息 ID，或给出非布尔发送标记，旧逻辑可能误确认或允许重试。文本、初始卡片与卡片更新现在把这些矛盾回执保守标为未知；明确未发送必须同时具备失败状态、布尔未发送标记且没有消息 ID。过长的文本发送消息 ID 也不会被确认。未知状态会阻止自动重发，仍需平台侧核实。

### 20. 同事池工具的位置参数绑定（中）

工具绑定包装器以前将内部函数放在第一个可位置传入的参数上，调用 `execute_tool` 并传入位置参数时会覆盖该函数，导致读写或目录工具失败。现在通过闭包固定内部函数，位置参数和关键字参数均正确转发；原有工作目录越界拒绝仍生效。

### 21. 已知未解决事项

* 本地模型响应可能违反请求中的 JSON 格式；意图路由实测不稳定，生产解析与降级行为需要单独核查。
* 默认 128 槽及 50 ms 轮询缺少面向真实模型、CPU、磁盘、SQLite 锁和外部 API 限流的容量证据。短任务测试不能推导生产吞吐；应在代表性负载下测量 P50/P95/P99、CPU、RSS、队列等待、锁等待及失败率，再设置并发和轮询参数。
* `FeishuCardKitAdapter` 在仓库文档中标记为未接线，且请求契约存在已知问题；不要依据模拟测试将其当作可上线的卡片链路。独立的 `task_progress` 插件仍依赖宿主编辑安全判定接口；现有旧版卡片补丁在当前宿主适配器的临时副本上因形态不兼容而拒绝写入。任务卡片桥已接入默认关闭的持久派发消费者，并在隔离进程经真实平台验证初始卡片和终态；未验证线上网关入站和升级后的端到端链路，也未实现细粒度百分比或阶段进度。未知发送或更新结果必须先核实，不能盲目重发。参见 `docs/reports/2026-11-03_interaction-delivery-survey.md`。
* 脱敏规则不覆盖所有路径形式（例如带空格的完整文件名或其他根目录），文件名本身也可能包含敏感信息；它不能视为全面的数据防泄漏控制。附件异常结果需要运营处理，尤其是 `unknown`：在平台侧核实前不得盲目重发。
* 本轮没有覆盖所有记忆、部署、插件和集群模块的全部路径，也没有完成生产负载测试或升级线上服务。

## 合成性能测量

在 WSL 的临时目录以标准库调度器运行：每轮提交 128 个任务，每项写入小文件并等待 25 ms；每种并发运行三轮。下表为各指标三轮中位数；延迟从调用提交开始计时至任务完成，包含排队，不含真实模型和网络。CPU 为进程累计 CPU 秒数，RSS 为单次进程峰值。它们是当时机器负载下的探索结果，不是生产基准或容量承诺。

| 并发槽位 | 总耗时（秒） | 任务/秒 | P95 延迟（毫秒） | CPU 秒 | 峰值 RSS（MiB） |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 8 | 0.438 | 292.4 | 403.5 | 0.118 | 26.6 |
| 32 | 0.172 | 746.3 | 146.2 | 0.207 | 27.7 |
| 128 | 0.185 | 692.6 | 156.1 | 0.242 | 30.2 |

这组短任务中 128 槽没有优于 32 槽，且 CPU 和内存更高；样本较小、波动明显，不能据此修改生产默认值。上线前应使用真实任务、生产队列和外部服务约束开展较长时间的并发阶梯测试，并观察 P99、错误率、内存、数据库锁等待和服务限流。

在增加桥接终态统计之前的代码上，在 WSL 临时 SQLite 库中放入 10 万条合成卡片记录，其中仅一条为未知状态，热缓存下各运行 9 次：原全表聚合中位 28.072 ms、最大 49.047 ms；索引查询中位 0.245 ms、最大 0.303 ms。两种实现的计数一致。这只是单机、少量异常的探索性测量；异常比例高、冷缓存或生产并发下的结果可能不同。

两个账号的隔离环境分别以标准库调度器、16 个槽位运行 10 批共 1280 个短任务，每个任务进行临时文件读写、越界拒绝和 5 ms 等待；各运行一次。本机耗时 2.51 秒、进程 CPU 3.50 秒，批末 RSS 从 27.47 MiB 增至 31.11 MiB；远端耗时 2.14 秒、CPU 2.97 秒，批末 RSS 从 27.32 MiB 增至 29.75 MiB。两边均无任务错误，每批结束活动槽位与任务 epoch 索引为零。这是数秒级合成检查，不能证明长时间内存稳定或生产容量；任务工作目录保留及磁盘增长仍需按实际证据保留策略管理。
