# 长会话与交付：升级验收项

旧实例排查显示，长会话的体验问题涉及多个相互影响的环节；不应假设更新或单次压缩就能全部消除。下列项目用于新版本验收，不包含用户会话正文。

1. **上下文增长**：记录压缩前后消息数和 token，确认压缩产物真的进入后续回合；连续读取大技能、重复工具结果后仍要保持在预算内。压缩失败、超时回退和临时继续旧上下文都要可观察。
2. **技能读取**：检查同一回合是否反复读取大技能文件。按照任务实际需要加载，避免不必要的全文重复；不能用“一律只允许一个技能”替代效果评估。
3. **重复消息**：按消息身份、来源、角色、内容和精确时间核实重复写入，并测试重连、压缩和并发场景。相同时间戳或内容不单独证明重复写入，更不能据此直接删除历史。
4. **完成回执**：分别观察后台任务回填、平台发送和主会话正常回复；`delivery_deferred` 只能说明对应回执被延后，不能单凭它判断所有聊天回复丢失。验证恢复、去重和附件送达。
5. **记忆召回**：记录召回子进程的无敏感信息错误分类、后端可用性及超时；服务进程存活不等于单次召回成功。诊断失败要让模型知道召回不可用，不能当作“没有相关记忆”。
6. **租约与并发**：核实旧租约持有者、过期时间和是否仍有活动工作。清理前须证明安全；不能只因一条记录过期就断言它导致当前延迟。用同会话与跨会话样例核对不丢、不串、不重复执行。

验收应在本机隔离 profile、合成或用户授权样例中进行，记录版本、时间、输入规模、延迟、工具调用和实际消息回执。部署到其他实例前，必须针对该实例验证相同链路；测试通过不等于模型答案语义一定正确。
