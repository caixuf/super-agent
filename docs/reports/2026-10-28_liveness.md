# 任务活体状态：从“已提交”到“还在做，做到哪”

日期：2026-10-28。范围：通用仓本地代码与测试；**未触碰 远端宿主**，未改任何生产 profile、未发外部消息、未启动模型。

## 结论

补上了长任务一直缺的那一层：**活体账本 + 只读状态工具 + guard 心跳/登记**。

- 后台终端不再只有“完成时通知”：转换时带 `heartbeat`，并在 `post_tool_call` 把 `session_id/pid` 登记进账本；
- 状态可被查询：`task_status` 返回 state、elapsed、heartbeat age、phase、progress、pid 健康、bounded tail；
- 进程消失是 `lost`，不是猜出来的 `done`；终态写一次，迟到心跳不能覆盖；
- 静默被显式分类：无 pid 且心跳超阈值 = `stalled`；pid 仍活 = `running`（附加 `quiet`），不误报死亡。

真实 pid 用例：启动 `python -c "time.sleep(30)"` → `inspect` 为 running → `terminate()` → `sweep` 变 `lost`，并断言状态不是 `done`。

本机合成演示（2s stall 阈值）：

```text
t=0  running pid_alive= True
t=3  running quiet= True heartbeat_age_s= 3.0
kill  running -> lost
final lost
```

它同时证明了两个容易混淆的结论：**进程活着但没输出** 仍是 running（附 `quiet`），**进程消失** 才是 lost；两者都不猜成 done。

## 行为边界

- `stalled` 是观察，不是判决：下一次 `beat` 可以恢复为 `running`；`lost` 也是非终态，重启后的新 attempt 可以重新登记。
- 没有记录时返回 `unknown_task`，不伪造成功；跨会话任务返回同一结果，不泄漏 label/tail。
- 账本不负责调度、渲染、平台投递；daemon 只产出 `task_state` 事件，卡片/消息适配器另行注入。
