# IM 前台、后台调度、同事与记忆收敛计划

规划日期：2026-11-02；实施状态更新：2026-11-07（Asia/Shanghai）。
规划初始基线：`e69f559`；当前已拉取并再次核对至 `dbd9074`（其上另有本地三提交，已推送至 `10b55bb`）。
状态：架构规划，P0 核对进行中，P1–P5 尚未完成；不代表已部署、已启用
或生产验收通过。当前代码证据及发版门禁见 `RELEASE_READINESS.md`。

## 1. 目标与范围

用户直接在消息平台或其他 IM 聊天的 Agent 就是前台。前台只负责交互、澄清、
派单、补充需求、查询、申请取消和汇报；实际调查、研究、编码、测试、
部署以及复杂任务规划均由后台执行。闲聊和解释已有结果不必建单。

先交付一个最小可靠闭环：

```text
用户 ↔ IM 前台 → 持久任务主账 → 一个后台 Worker 执行路径
          ↑          ↑                  ↓
          │          └──── 结果、证据与任务事件
          └── 统一汇报/发送出口 ← 已校验事件与交付账本

记忆：前台/后台按权限读取；候选知识异步审查入库，不阻塞交互。
```

初始阶段只作规划；目前已推进前台权限、回合交接及只读纵向链路的隔离实现和测试，
详见 `FRONTDESK_BOUNDARY.md`。生产配置、服务重启、真实消息、
生产记忆写入和积压消费须在明确目标与授权窗口后单独进行。

暂不做：动态招聘、人事 Agent、多层自主委派、多主机协调、第二套调度器、
更换记忆数据库、自动策略晋升、重写卡片 UI。现有功能和历史记录不直接删除。

## 2. 架构决策与依赖方向

采用“薄前台 + 持久任务核心 + 按需执行同事 + 独立交付与记忆服务”。
不采用“主 Agent 既聊天又执行”，也不采用“每个同事必有常驻 Gateway”。
代价是需要显式任务接口、事件和权限配置；收益是任务不占聊天回合，
身份与经验不依赖进程常驻，失败恢复不依赖前台上下文。

| 边界 | 唯一职责 | 优先复用 | 对外接缝 |
| --- | --- | --- | --- |
| IM 前台与宿主适配 | 交互、可信身份绑定、工具白名单 | Hermes 插件/工具集、`plugins/durable_dispatch/` | 提交、查询、补充、取消、澄清答复 |
| 任务核心 | 权威任务身份、归属、依赖、租约、尝试与结果 | `pool.py`、`worker.py`、`scheduler.py` | 现有 Pool/Worker 契约，缺口最小扩展 |
| 补充与工作流 | 需求版本、交接、阶段推进 | `follow_up_store.py`、现有 workflow 组件 | 绑定任务的持久命令与确认事件 |
| 后台执行/验收 | 执行工具、产物、证据与停止证明 | `analysis_runner.py`、经核验的开发执行器 | 管理员固定 argv + 结构化回执 |
| 同事目录 | 稳定成员、岗位、权限引用、实例代次 | `colleague_registry.py` 等 | 可信成员绑定，不自行调度或发送 |
| 状态与交付 | 状态投影、汇报组织、唯一渠道发送与回执 | liveness、completion/outbox、宿主 transport | 从已校验任务事件到发送账本 |
| 记忆 | 有权限的召回、候选审查、索引与版本 | `agentcore/memory/` | 现有检索与准入接口 |

宿主插件、IM/模型/执行器适配器依赖核心契约；核心不反向导入 IM、CLI
或业务平台。宿主注入 transport、模型和执行策略，不由任务文本选择可执行程序。
复用现有接口；没有真实调用需要时，不先新增统一框架或抽象基类。

任务主账、心跳、工作流和交付记录不必塞进一张表，但必须有明确映射：
任务主账决定执行状态；liveness 是活体证据；验收状态表达证据是否满足；
交付账本决定用户是否收到消息。它们不能独立把同一个任务判成“完成”。

## 3. 不可退让的行为契约

- 前台执行工具按宿主白名单硬隔离，包括插件工具及间接执行通道；
  不能只靠 SOUL 提示词。前台不得调用 shell、代码执行、任意文件写入或长时间等待。
- 派单必须先持久化再确认接单。完成确认后结束前台回合；后台继续运行。
  派工不可用时明确报错，不静默换执行器、不让前台亲自接管。
- 用户/团队/profile/会话/路由由宿主认证和绑定，不信任模型提供的 owner。
  初版保持现有同会话授权边界；跨 `/new` 查询或接管旧任务需单独授权设计。
- 同一请求重试使用同一幂等键；超时代表结果不明，不代表未接单。
  有副作用任务默认不自动重放；外部效果不明时保留现场并进入待核对流程。
- 一个任务绑定一个来源路由、执行成员/代次和 attempt。前台重启不丢单；
  新一轮用户输入不等待旧任务完成。上下文压缩后仍能按授权从主账恢复。
- 补充需求持久绑定任务及版本；只有执行方确认后才叫“已应用”。
  不可逆阶段的补充必须明确阻塞或另建后续任务，不口头声称已改变在途动作。
- 取消先记录请求，确认本次工作及受控后代停止后才能宣称已取消。
  Worktree 只提供工作区分离，flock 只提供互斥，都不是安全沙箱。
- 前台持有用户目标和验收标准；工具验证由后台执行。
  模型成功声明、回执格式合格、技术验收通过、消息送达必须分开表达。
- 一个对外发送出口。后台只产事件与产物，不直接发 IM；
  简单进度用模板，复杂结果由前台受限汇总回合组织，再经同一出口发送。
  汇总回合不得把后台结果当新用户任务再次派单。
- 发送未知时持久记录并核对，不自动盲重发，不承诺外部消息 exactly-once。
  正常前台对话回复与后台通知也要划清所有权，不能同时生成两份最终回复。
- 模型、超时、输出、并发与存储预算由宿主配置；记录实际调用与资源用量。
  未经实测不把某个模型别名或线程池当作速度、质量、成本保证。

## 4. 阶段与出口

顺序为 P0 → P1 → P2 → P3 → P4 → P5。P3 的身份和记忆授权要求在
P1/P2 就必须满足，P3 不是延后补安全；后置的是丰富岗位及经验共享。
每阶段可以独立提交和回退；前一出口未通过，不因后续功能已写好而跳过。

### P0：冻结边界、盘点真实接线

- 核对当前入口、任务池、Worker、工具集、成员、状态与发送者的真实调用关系；
  仓库实现与隔离测试先查，线上盘点只读且不输出密钥、对话正文。
- 确认现有 `durable_dispatch` 只读范围；通用 colleague Worker 的可信
  containment 当前不可用，不通过改布尔值、删门禁或虚构 readiness 解锁。
- 找出研发岗位/编排器对业务 DSL、`autotest_server` 等的依赖，列为业务叠加层迁移项。
- 对齐旧文档冲突：主同事亲自执行验证、默认直接对话其他同事、招聘优先等
  不作为本次首版目标；保留历史记录，不把计划写成当前能力。
- 选定一个隔离测试 profile、一条只读后台路径及后续写任务的可信执行边界。
  复用现有部署入口；不因架构收敛另写安装器。

出口：当前/目标链路表、唯一状态与发送所有者、改动清单、测试基线及阻断项。
若全工具执行边界尚不可证明，只允许推进只读闭环，不声称支持完整研发任务。

### P1：薄前台 + 只读后台纵向闭环

- 在隔离 profile 配置前台工具白名单，允许必要且有预算的记忆读取，
  只暴露已接通的任务操作；未接通操作返回明确不可用。
- 复用现有持久派单和只读 runner，执行槽位由 `worker_concurrency` 配置
  （默认 1，上限 16），一个前台回合可提交多个后台任务并发执行；前台不轮询等待。
  在宿主可控边界验证派单确认后结束回合，不能仅依赖工具返回的自然语言指令。
- 复用 outbox/direct completion 走唯一出口，先以替身 IM 验证事件、
  结果与汇报；复杂汇总不得接回执行工具或重复任务入口。

出口：提交后后台未完成时，前台可继续接第二条消息；无执行工具逃逸；
派单去重、失败反馈、重启恢复、双用户/双会话隔离、路由绑定均有证据。
这是只读 MVP，不把它称为完整研发执行已接通。

### P2：一条受控研发执行路径与生命周期

- 选定一个实际模型/工具执行器，管理员固定入口；优先复用现有开发 runner，
  先核验其业务依赖、工作树创建、工具范围、模型路由及回执可信程度。
- 开发仅在隔离工作树，默认不自动合并、发布或部署；保留原工作区和失败产物。
  全工具任务必须有可信任务级进程/容器边界、文件和凭据权限策略及停止证明。
- 执行与验收分步记录；首版用明确命令、产物校验和受控审查，
  不默认拉起完整八岗位流水线。语义审查不能冒充确定性证明。
- 接通补充、澄清、取消、截止时间与崩溃恢复；命令收到与实际生效分别回执。
  跨数据库动作使用稳定命令键和恢复核对，不宣称天然原子。

出口：一条真实模型的隔离小型研发任务产生可回读变更和测试证据；
取消、超时、后台后代残留、旧 attempt 回执和外部效果未知的反例通过。
若停止证明缺失，保留未知/占用，不强行结算或重派。

### P3：同事配置收敛，不扩组织系统

- 同事定义为稳定身份、岗位、权限、记忆绑定和执行配置；进程按需启动。
  常驻身份不等于常驻模型连接。保留已有成员 ID 与历史任务归属。
- 初版只配置执行与审查/验收能力；岗位可扩展，不在核心固定业务团队名册。
  将业务岗位及桥接迁入叠加层，已有调用方通过明确兼容接缝迁移。
- 角色、权限、成员 ID 和实例代次分开；权限撤销后不得继续接受新派单。
  动态招聘、自动授权、多层委派不进入首版关键路径。

出口：同一成员跨任务可识别、权限受宿主约束；换模型/重启不丢归属；
角色描述不能提权；业务平台缺失时通用路径仍可工作。

### P4：记忆读写收敛与隔离评测

- 不更换事实库；复用 FTS/向量检索和 L1 索引 → 按需详情。
  前台只取有预算的相关偏好/决定，后台取本任务所需知识；不广播完整会话。
- 区分用户长期偏好、岗位经验、明确发布的团队知识和任务临时上下文。
  团队可见性必须有受信授权，不通过放宽 agent/profile 过滤来“实现共享”。
  用户偏好与任务约束以最小必要快照交接，不能跨用户无条件复制。
- 任务状态、执行日志、一次性命令不入长期事实库；记忆故障不能阻塞派单，
  也不能表现为“确定没有相关历史”。
- 先做只读召回；再在临时库验证异步自动准入：提取、审查、冲突、索引、
  精确召回验证及审计。技术经验须绑定已验收证据；不把助手自述当事实。
- 共享知识的发布、更正、撤销及索引可见延迟必须可追溯。过期或撤销来源
  不应因旧摘要仍命中而继续作为当前事实使用。

出口：重启/跨会话召回、相关性、误召回、错误准入、重复、冲突和
跨身份泄漏有固定样本与可复现指标；安全反例零泄漏、零凭据准入；
质量阈值在评测前冻结，并与关闭记忆基线比较。合成测试不能替代真实模型评测。
生产自动写入、历史积压处理和策略自动晋升仍须分别授权和验收。

### P5：真实 IM 灰度、回退与可复现交付

- 在授权的私有测试会话验证真实模型任务、插话、澄清、补充、取消、
  文本和附件回读；再人工核对客户端呈现。平台回执不等于客户端已看见。
- 真实渠道交付验收独立保留；本计划和文本 MVP 都不能替它解除。
  未通过的卡片模式保持关闭，不同时启用两个卡片或最终消息生产者。
- 经授权后才迁移指定生产 profile；先停新接单、排空/核对在途任务，
  备份版本和配置，选择唯一新入口。未知在途效果未解决时不得切到旧入口重复执行。
- 演练关闭新接单、保留查询与待交付结果、恢复旧配置/版本；
  不删任务库、不覆写生产记忆、不自动重放历史积压。
- 使用现有受管安装、doctor、回滚与干净室入口验证重装；
  Docker 通过不能替代实际宿主与真实 IM 验收。

出口：逐项证据、实际启用清单、未通过项、观测数据和已演练回退步骤。
只有通过全部对应出口的能力才允许对外称为已上线。

## 5. 验证与观察

| 维度 | 必测场景 / 观察项 |
| --- | --- |
| 前台响应 | 后台长任务运行时继续接新消息；首响、接单确认、可再次交互耗时分别测量 |
| 调度可靠性 | 重复提交、依赖失败、租约过期、重启、旧回执、队列满、权限撤销 |
| 生命周期 | 补充的收到/生效、不可逆阶段、取消请求/实际停止、超时与后代残留 |
| 交付 | 双用户/会话/线程、`/new`、文本/附件部分成功、网络超时、未知发送重启核对 |
| 验收真实性 | 文件缺失、命令失败、伪造证据、过期产物不能显示已验收完成 |
| 记忆 | 私有/共享授权、错误准入、冲突、索引失败回滚、更正撤销、跨会话与错误召回 |
| 成本与负载 | 排队/执行/交付延迟、并发、调用次数/token、结果大小；无法测量的成本明确缺失 |

先复跑现有 pool/scheduler/worker、durable dispatch/completion、follow-up、
liveness、同事权限及 memory 专项；再补覆盖上述纵向闭环的测试。
真实凭据和外部发送默认不参与本地回归。全量检查先审核入口副作用，
仅在隔离配置中运行；跳过逐项说明，不计为通过。

历史参考而非本计划验收：上一轮会话的相关专项为 128 passed、8 skipped，
跳过为可选原生调度绑定；其中同事 Worker 的通过测试包含“正确拒绝执行”。
该数字仅是规划时的历史参考；当前实施证据及剩余门禁统一记在
`RELEASE_READINESS.md`，不能用历史计数声称当前源码或生产已验收。

首响、吞吐和召回质量先建立现状基线，再在灰度前确定可接受阈值；
不在未知网络、模型与硬件条件下承诺固定秒数或收益。

## 6. 下一步与授权边界

P0 当前链路与差距表已记录在 `RELEASE_READINESS.md`。P1 权限和回合交接
已有隔离实现；真实模型、服务重启和实际 IM 纵向验收仍未完成，不能跳到已上线结论。
继续沿只读闭环补证，不同时开工所有阶段；写任务能力单独过门。
模型和资源策略采用宿主受信配置，未经用户选择不擅自购买或新增付费依赖。

本规划不授权提交推送、部署、重启服务、真实 IM 外发或生产记忆处理。
后续实现也不得借“收敛”删除既有数据、关闭未知现场服务或绕过已有安全门禁。
