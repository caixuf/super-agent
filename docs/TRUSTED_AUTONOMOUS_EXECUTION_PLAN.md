# 可信自主执行实施计划

- 编制日期：2026-11-09（Asia/Shanghai；America/Los_Angeles 为 2026-11-08）。
- 状态：**待执行计划，不是已完成的能力或验收报告**。
- 调研基线：本地 `main`，HEAD `1c6d102`，另有既存未提交修改；不是干净发布输入。
- 适用范围：从现有通用 Agent 底座推进到有限授权下的可信自主编码执行。
- 执行授权：本文不授权生产切换、服务重启、真实消息外发、生产记忆写入或自动合并部署。

## 1. 目标与边界

首版目标：在指定测试仓库中，Agent 独立完成一项有限代码修改，由可信执行器验收，交付可审查补丁；中途可取消、可恢复，不越权，不把失败说成成功。

首版不做：自动合并、自动部署、自主扩大权限、自动晋升生产技能、全岗位并行研发和高并发容量承诺。已有实现不能因为列入本计划就被视为已启用或已验收。

五项独立的验收要求：

| 要求 | 必须提供的证据 |
| :--- | :--- |
| 结果可验证 | 实际代码差异、固定验收项、原始执行结果和产物摘要 |
| 权限可约束 | 授权仓库、路径、工具与网络的执行前检查，以及越权被实际拒绝的记录 |
| 执行可停止 | 绑定该 attempt 的执行环境及受控后代停止证明 |
| 故障可恢复 | 崩溃、重启、旧回执与重复请求不会造成错误终态或未知副作用盲重放 |
| 交付可核对 | 原始任务和会话绑定；已生成、已验收、已送达分别记账 |

单测通过、服务 active、模型自报完成及文件生成，均不能单独替代上述要求。

## 2. 现状依据与复用原则

以下为调研基线中的观察，实施前须重新核对对应代码，不能当作持续运行状态：

1. [`colleague_dev.py`](../agentcore/colleague_dev.py) 的独立兜底流水线包含按迭代次数计算评审分数和生成简单用例骨架的路径。它不能充当真实模型研发、评审和测试通过的证据。
2. [`colleague_worker.py`](../agentcore/colleague_worker.py) 的 `_trusted_containment_available()` 返回 `False`；[`colleague_containment.py`](../agentcore/colleague_containment.py) 中对 unit/container 的观察尚不构成完整 attempt 绑定证明。不能直接改布尔值或放松证明规则来解锁。
3. [`dev_runner.py`](../agentcore/dev_runner.py) 与 [`verification_gate.py`](../agentcore/verification_gate.py) 已提供管理员验收策略、工作树锁和验收回执。应补强证据绑定，不新建第二套验收系统。
4. [`acceptance_capture.py`](../agentcore/acceptance_capture.py) 与 [`acceptance_evidence.py`](../agentcore/acceptance_evidence.py) 已提供采集与一致性审计；[`real_link_acceptance.py`](../checks/real_link_acceptance.py) 的部分检查直接操作临时 Pool，不能据名称当作真实渠道验收。
5. [`skill_forge.py`](../agentcore/skill_forge.py) 已提供案例与程序性技能机制，runner 有成功后案例记录路径；仍须补齐可信准入、隔离、撤销与晋升边界。

实施纪律：

- 任务、attempt、租约和终态仍由现有 Pool 仲裁；StateGraph 负责编排，不另建竞争主账。
- 复用现有监管器、权限接缝、验收回执和交付出口；不创建平行的任务池、健康账本或发送者。
- 保留源码存在、实例配置、真实验收三层区别；历史报告不得外推到新版本。
- M0—M5 只是本计划的里程碑，不替换现有发版门禁编号或运行状态枚举。

## 3. 里程碑与执行顺序

```text
M0 真实判定与基线
  → M1 可信执行边界
  → M2 单任务真实研发闭环
  → M3 取消、恢复与副作用控制
  → M4 真实前台与交付验收
  → M5 受控经验复用与灰度
```

当前 M0—M5 均为待执行，未指定负责人或承诺工期。执行开始时登记负责人、候选版本、目标环境、授权范围与证据位置；每过一个里程碑，只开放对应能力。

### M0：建立基线，消除假成功

**目标：** 让失败、模拟结果、缺失验收和未知状态不会被报告为已验证成功。

工作项：

- [x] 将模拟兜底限制在显式 demo/test 模式，真实模式桥接不可用时明确失败或报告不可用，不静默生成成功结论。
- [x] 收口成功判定：执行完成、验收通过、产物有效与交付确认分开，不能仅信模型 `ok` 或自然语言结论。
- [x] 明确任务类型的必需验收项；编码任务缺少必跑检查时，不以空检查集合判定已验证成功。不无差别破坏允许无检查的既有底层接口。
- [x] 核对并隔离既存未提交修改，冻结源码、宿主、配置摘要、启用能力和测试环境。
- [x] 对齐能力与发版文档；保留历史证据及其提交范围，移除对当前版本无依据的完成声明。

复用位置：`colleague_dev.py`、`dev_runner.py`、`verification_gate.py`、`RELEASE_READINESS.md`、`RELEASE_CAPABILITIES.md`。

退出条件：

- 模型自报成功、桥接异常、空必需验收、缺产物、超时和损坏回执等反例不能进入已验证成功。
- 固定基线完成一次完整验证，逐项记录跳过原因；关键门禁跳过不算通过。

### M1：实现任务级可信执行边界

**目标：** 证明任务从启动起就在受控边界内，而不是停止时才靠名称或环境变量猜测归属。

工作项：

- [x] 在现有 systemd/container 接口中评估并选择一个执行后端先落地；评估同时覆盖停止能力、文件系统、凭据、网络和可逃逸入口，不把 cgroup 本身当完整沙箱。
- [x] 由可信宿主创建 attempt 专属执行环境，持久绑定任务、attempt、不可变实例标识和启动代次；绑定信息不能由任务 payload 自行声明。
- [x] 模型工具执行和独立测试执行都进入授权边界；禁止把工作委托给边界外常驻 Gateway 后仍声称完整 containment。
- [x] 落实可写目录、工具和网络策略，禁止访问宿主凭据与控制套接字等高权限入口；将岗位路径规则接到实际执行前检查。
- [x] 设置时间、进程数、内存、输出及磁盘预算；超限处置有界，不能只监控不阻止。
- [x] 取消先阻止新动作，再停止执行环境并核验受控后代。缺失实例、查询失败或绑定不符保留未知，不伪造停止证明。
- [x] 证据满足要求后，仅对已验证适配器开放可信门禁；其他执行器继续默认拒绝。

复用位置：`attempt_supervisor.py`、`colleague_containment.py`、`colleague_worker.py`、`verification_gate.py`；现有 `checks/systemd_containment_probe.py` 仅作局部探针，不升级为生产证明。

退出条件：

- 越权读写、未授权网络访问和策略故障的反例实际被拒绝。
- 普通子进程、脱离会话的子进程、超时与 Worker 崩溃均有真实进程验证。
- 伪造 token、复用名称、旧实例或旧停止回执均不能通过；有后代残留时不得报告执行已停止。

### M2：跑通单任务真实研发闭环

**目标：** 先让一个执行岗位修复测试仓库中的明确 bug，不以岗位数量衡量闭环完成度。

固定链路：接单 → 冻结范围与验收契约 → 隔离工作树 → 真实模型修改 → 可信执行器验收 → 核对补丁与产物 → 交付人工审查。

工作项：

- [ ] 首个样板任务采用小型测试仓库和明确失败测试，真实调用模型，不使用模拟评分或固定输出代替。
- [ ] 必跑检查取自受信策略，执行前冻结；模型不能删改检查后自证通过。独立评审意见不替代测试结果。
- [ ] 增强现有回执，绑定 task、attempt、代码快照、策略版本与执行来源；摘要用于完整性核对，不能独立充当可信来源证明。
- [ ] 将可信验收材料与 Agent 可写区隔离；验收后代码变更或使用其他任务回执时，旧验收不得继续有效。
- [ ] 产出可回读补丁、文件清单、原始验收日志与摘要。收割前保留工作树，未持久化产物不得清理；默认不合并。

复用位置：`dev_runner.py`、`verification_gate.py`、`state_graph.py` 与现有 Worktree 管理。

退出条件：

- 真实模型完成代码修改，可信执行器执行固定检查，产物与报告能由宿主回读。
- 仅改验收掩盖问题、冒用旧报告、验收后篡改代码、补丁未保存和工作树提前清理等反例被拦截。

### M3：补齐取消、恢复与副作用控制

**目标：** 故障路径也保持可控、诚实，而非只证明正常路径能成功。

- [ ] 将下表故障矩阵纳入可重复回归，主账、执行边界、产物与交付状态可关联核对。
- [ ] 补充消息区分收到与执行方已应用；需求或授权范围变化后重新确认契约，不静默扩大权限。
- [ ] 对授权工作区内可逆修改和不可逆外部动作分级；推送、合并、部署、删除及外发首版审批或禁用。
- [ ] 重试授权不自动包含重放外部副作用；预算耗尽有界停止或转人工。

| 场景 | 必须行为 |
| :--- | :--- |
| 执行中取消 | 取得停止证明后才确认执行已停止 |
| 取消与成功竞争 | 按同一主账规则仲裁，无矛盾终态 |
| Worker/宿主重启 | 核对原 attempt，不能盲目启动第二份执行 |
| 租约失效或旧 attempt 迟到 | 旧执行及回执不能覆盖新 attempt |
| 重复提交 | 按既有身份与幂等契约处理，不扩称跨队列全局幂等 |
| 模型重复无效调用 | 有界停止并报告原因 |
| 外部动作响应丢失 | 保留 unknown，核对后决定，不盲重放 |
| 时间、资源或调用预算耗尽 | 有界停止或转人工，不自行增加额度 |

复用位置：`pool.py`、`worker.py`、`attempt_supervisor.py`、`plan_gate.py`、`hitl_bridge.py` 与现有交付账本。

退出条件：故障矩阵有可重复证据；无法证明的状态如实保留未知。不承诺超出外部系统能力的全局 exactly-once，也不把进程停止等同于撤销既有副作用。

### M4：真实前台与交付验收

**目标：** 验证用户实际经过的链路，而非仅手工操作临时 Pool。

- [ ] 明确授权测试 profile、测试会话、账号和时间窗口；不自动向生产渠道发消息。
- [ ] 接单后前台确定性释放回合，后台运行期间仍能处理第二条消息。
- [ ] 查询、补充、取消准确绑定任务及授权身份；跨会话访问按策略拒绝。
- [ ] 重启后查询可用，结果回到原始会话；已知回执去重，不确定发送先核对。
- [ ] 分别验证文本、附件和卡片；不可回读的正文或呈现效果标记未验证，不以消息 ID 替代全部交付证据。
- [ ] 将 Gateway、Queue、Transport 三方证据接入现有采集与审计入口；采集缺口不能当作没有异常。

复用位置：前台边界补丁、`acceptance_capture.py`、`acceptance_evidence.py`、现有投递模块；临时 Pool 场景继续作为组件测试保留。

退出条件：同一窗口内的入站、接单、后台执行、第二消息、终态、交付和恢复均可对账。每种宣称支持的交付形式分别记录通过、失败、未验收或不适用。

### M5：受控经验复用与灰度

**目标：** 在可信执行之后积累经验，避免将假成功自动固化为技能。

- [ ] 案例绑定真实验收证据，不能只凭 `ok=True`、固定质量分或模型自评成为优质案例。
- [ ] 区分候选经验、审核通过技能与撤销技能；首版允许采集候选，不自动晋升生产技能。
- [ ] 按 profile、主体及团队隔离存储与读取，覆盖未授权访问和撤销后读取反例。
- [ ] 技能只能作为参考输入，不得覆盖权限、任务契约或必跑验收。
- [ ] 低并发、低风险灰度，记录任务类型、人工接管率、错误成功率、停止耗时、资源消耗和交付异常；阈值在验收前按环境冻结，不把一次测试数字当 SLO。
- [ ] 演练停止接单与版本回滚，保留在途任务、状态库和未知投递记录；代码回滚不等于撤销外部动作。

复用位置：`skill_forge.py`、记忆身份路由与现有受管部署/回滚入口。

退出条件：能明确列出允许自主执行、须审批和禁止的任务；技能可追溯、可撤销、不串身份，灰度退出与回滚有实测证据。

## 4. 第一批交付范围

第一批仅做 M0 和 M1 的最小切片，不代表完成两个里程碑的全部出口：

- [x] 禁止真实路径静默进入模拟成功。
- [x] 建立独立测试 profile 与测试仓库，不使用生产队列或生产记忆。
- [x] 打通一个 attempt 专属可信执行后端。
- [x] 证明可以受控修改文件，也能停止该 attempt 及受控后代。
- [x] 将正反例纳入回归，保存版本绑定证据和明确限制。

第一批不新增岗位、不做自动合并部署、不提高并发、不启用自动技能晋升。M2 的真实模型闭环在可信边界就绪后实施，不以第一批简单文件修改代替。

## 5. 交付与证据记录规则

每个里程碑至少记录：

| 字段 | 内容 |
| :--- | :--- |
| 负责人和范围 | 实施负责人、评审/验收责任人、允许与禁止动作 |
| 输入身份 | 源码提交或候选摘要、宿主版本、策略与配置摘要、环境和时间窗口 |
| 场景与结果 | 正向场景、故障反例、原始命令和结果、跳过原因 |
| 执行证据 | task/attempt/执行实例绑定、代码与产物摘要、验收和停止回执 |
| 交付证据 | 原始会话绑定、平台回执、可回读内容及不可核实项 |
| 结论和回退 | 通过、失败、未验收或不适用；限制、阻断项与回退步骤 |

证据遵循现有产物留存策略；本机临时路径不能冒充已归档的 CI 证据。不得保存真实凭据或未经授权的任务/记忆正文。本文清单仅在对应证据完成后勾选；完成一个里程碑不等于全部发版门禁通过。
