# toolsets/ — 通用工具面适配件（机制，不含业务工具）

本目录放的是**与业务无关的工具面适配机制**。业务平台自己的工具面（工具注册表、具体工具实现、
平台 MCP 服务本体）**不属于本仓**，由业务叠加层提供。

## 内容与边界

| 路径 | 是什么 | 为什么通用 |
| :--- | :--- | :--- |
| `pi_executor/` | **外部编码执行器适配器**：在隔离目录里以参数数组拉起一个外部 coding-agent CLI，以 JSON 事件流（不是 exit code）判定成败，超时/取消时清理整棵进程，产出**结构化回执**（不含 prompt 与工具参数） | 它只做「一次执行 + 一次回执」，不接管任何调度权威；换任何外部引擎都是同一份形状 |

## 明确**不在**本仓的（业务叠加层提供）

- **平台工具注册表 / 能力分层表**（记录本平台有哪些工具、各属哪层）—— 那是业务契约面，
  工具名就是业务名词，写进通用仓等于把业务焊死。
- **平台工具的具体实现**（例如「调用本平台某接口的某个工具」）—— 同上。
- **平台 MCP 服务本体与其依赖清单**——依赖与工具面都是业务的。
- **嵌入协议翻译层**（OpenAI 兼容 ↔ 某个上游厂商协议）：机制本身通用，但它是**业务 MCP 服务
  目录下的一个伴生件**，其部署位与凭据都挂在业务侧，因此随业务叠加层一起走，不在本仓留副本。
  （判定口径见下——「换一个行业还要不要它？」要，但它的**部署位**是业务的，这里按部署位切。）

判定口径很简单：**「换一个行业还要不要它？」** 要 → 通用；不要 → 业务叠加层。
**并有第二条：即使机制通用，只要它的部署位/凭据/被谁 import 是业务的，也留在业务侧**——
把这类件搬进通用仓，只会造出一份谁都不跑、且很快与真实实现漂移的副本。

## 这些副本是骨架，部署时才接线

`install/install.sh` 会把 `toolsets/` 下的子目录拷到 `<DEPLOY_DIR>/toolsets/`。落位后
**还需要宿主做两件事**：

1. **设置环境变量**（本目录的代码用它们定位 Hermes 配置与隔离目录，不再硬编码画像名）：
   - `HERMES_HOME` —— 宿主 Hermes home（首选）；
   - `HERMES_PROFILE` —— 无 `HERMES_HOME` 时的画像名，缺省 `default`；
   - 另有 `PI_EXECUTOR_*` 系列覆盖项（CCP 凭据解析唯一实现位于 `agentcore/ccp_config.py`；`pi_executor/ccp_config.py` 仅保留兼容导出；其余开关见 `driver.py` 里的 `os.environ.get`）。
2. **改导入路径**：`pi_executor` 是纯标准库的相对导入包，可直接用；把执行器包进工具面的那层
   **胶水**属于业务工具，宿主按自己的包布局写。

> 注意：这个件在本仓**只是可复用副本**，本仓不 import 它、也没有它的测试。
> 它在业务仓里有真实调用点与单测；改动请以那边为准，改动后同步回来。
