# 完整版发版能力表

编制日期：2026-11-03。本文定义建议的发版核对范围，不是当前功能已通过的声明。
当前实现与未完成门禁以 [RELEASE_READINESS.md](RELEASE_READINESS.md) 为准；
本文未重新执行运行验收，也不改变既有修复方案、功能开关或生产配置。

## 1. “齐全”的定义

一次业务机器人发版必须同时点名三份交付物，不能只发通用代码：

| 交付物 | 必须记录 | 不应混入 |
| --- | --- | --- |
| 通用核心 | 源码提交、包摘要、能力清单、插件与补丁清单 | 业务秘密、目标环境凭据、生产状态库 |
| 业务适配包 | ID/版本、兼容范围、身份、技能、工具、业务流程、记忆映射及依赖 | 另一套任务调度或投递主账、凭据值 |
| 实例部署清单 | 有效 home/profile、服务、实际路径、权限、开关、资源预算、凭据名称及引用 | 密钥明文、会话正文、记忆正文 |

三者连同 Hermes、HFC、模型/执行器及嵌入后端身份组成一个经验证的兼容组合。
外部依赖可以按明确版本另行安装，不要求全部塞进同一个归档；但不能遗漏版本、
安装来源、平台限制和验证证据。发布报告只记录脱敏路径标识或摘要。

**完整交付 ≠ 所有模块默认开启。** 本文主表是建议的“完整版”范围。
发布负责人须在冻结前确认范围；主表能力未通过，不能临时改成可选以获得全绿。
若主动缩小范围，可以发布明确命名的基础版/只读版，但不得称为完整版。
可选扩展也必须列明支持、关闭或不支持，不能留成隐含承诺。

## 2. 通用运行能力

以下各项均须在完整版报告中独立验收；代码入口只是定位线索，不是通过证据。

| ID | 对用户的能力承诺 | 主要责任/现有入口 | 最小验收出口 |
| --- | --- | --- | --- |
| C01 | 正常对话与连续会话 | Hermes 宿主、渠道适配 | 真实模型正常回复；连续消息、会话重置、错误反馈明确；不丢消息、不串会话 |
| C02 | 前后台职责可解释 | 宿主策略、`plugins/durable_dispatch/` | 声明当前运行模式；若启用薄前台，执行权限由程序硬隔离，派单后结束回合，后台忙时仍接新消息 |
| C03 | 长会话不静默退化 | 宿主上下文、`agentcore/model_context.py` | 长输入与多轮工具结果下验证压缩真的进入后续回合；失败可见；记录正确性、耗时及预算 |
| C04 | 工具真的可用且有权限边界 | Hermes 工具集、插件、`agentcore/capability_guard.py` | 已启用工具可发现并能调用；直接和间接入口均覆盖；未知身份、损坏策略及权限撤销有反例 |
| C05 | 先保存任务再确认接单 | `agentcore/pool.py`、`plugins/durable_dispatch/` | 返回稳定任务号；同请求幂等；提交超时不冒充未接单；跨身份访问拒绝 |
| C06 | 独立后台只读执行 | `agentcore/worker.py`、`agentcore/analysis_runner.py` | 真实模型分析受限材料，报告及引用可回读；前台退出不丢任务；路径、输出和并发预算受限 |
| C07 | 受控编码与测试 | `agentcore/dev_runner.py`、受信执行适配器 | 真实模型产生隔离变更和独立测试证据；执行器、命令、文件与凭据范围受控；不默认合并或部署 |
| C08 | 补充需求与澄清 | `agentcore/follow_up_store.py`、工作流/宿主接线 | 补充绑定任务和版本；区分收到与执行方已应用；不可逆阶段明确拒绝、暂停或另建后续任务 |
| C09 | 状态与进度可信 | Pool、`agentcore/liveness.py`、状态工具 | 区分排队、运行、等待、停滞和未知；进度有事件依据；心跳投影不能擅改主账终态 |
| C10 | 取消与超时有停止证明 | `agentcore/attempt_supervisor.py`、Pool/Worker | 先记取消请求，确认本 attempt 及受控后代停止再终结；证明缺失保留未知/占用，不冒充取消完成 |
| C11 | 重启恢复不制造重复副作用 | Pool/Worker、attempt 与恢复协议 | 独立服务重启、在途崩溃、旧 attempt 回执均有反例；完成任务不重跑；未知外部效果不盲重放 |
| C12 | 结果回到正确的人和会话 | `agentcore/completion_delivery.py`、outbox、宿主 transport | origin 固定绑定；发送与确认分别记账；断线/重启后核对；发送未知不盲重发，不承诺外部 exactly-once |
| C13 | 进度卡与最终答复一致 | HFC、`integrations/hfc/lock.json` | 一个交互所有者；真实客户端验证创建、更新、终态、连续消息与插话；不暴露私有推理；原生备用生产者不并行启用 |
| C14 | 报告、图文与附件可读取 | `plugins/markdown_delivery/`、`plugins/illustrated_delivery/`、宿主渠道 | 文本、图表和附件样例实际送达并由目标用户打开；权限、截断和渲染错误明确，不以生成文件代替交付 |
| C15 | 同事身份、岗位与执行对应 | `agentcore/colleague_registry.py`、目录/派工接线 | 身份跨任务稳定；岗位、权限、记忆与执行代次可追溯；名册存在不等于实例就绪；撤销后不可继续越权 |
| C16 | 长期记忆可存储和维护 | `agentcore/memory/`、记忆服务 | 写入、去重、冲突、更新及恢复有证据；重启后可读；维护失败不破坏原库；嵌入身份与维度匹配 |
| C17 | 新会话自动召回 | `plugins/localvec/`、记忆路由 | 真实新会话命中固定样本；无结果与服务故障分开；身份与代际隔离；记录误命中、延迟及预算 |
| C18 | 对话经验受控入库 | `plugins/memory_bridge/`、`agentcore/memory/memory_autonomy.py` | 捕获不阻塞前台；候选经审查后入库；错误准入、冲突、重复和失败可审计；真实模型评测不由合成测试替代 |
| C19 | 授权共享长期知识 | `agentcore/colleague_shared_memory.py`、身份路由 | 个人/团队/成员授权明确；授权发布的知识可召回，未授权读写拒绝；撤销生效；会话历史不因共享记忆而共享 |
| C20 | 模型与资源使用可控 | `agentcore/model_routing.py`、`agentcore/ccp_config.py`、执行策略 | 记录实际模型及超时/并发/token/输出预算；路由故障和降级显式；不能靠别名宣称质量或成本保证 |
| C21 | 高风险操作受控 | 写保护、审批、执行与宿主权限边界 | 指令文件、发布部署、凭据及工作区权限按策略限制；审批超时不当同意；工作树和文件锁不冒充安全沙箱 |

C02 的运行模式必须与当前收敛方案一致。旧文档中的“完整主 Agent”与新计划的
“薄前台”不能在同一实例上被同时当作默认事实；业务提示词无权改变宿主硬权限。
其中 C15 不要求动态招聘或每人常驻一个 Gateway，C19 不要求开放所有人的记忆。

## 3. 业务适配能力：单独交付、联合验收

业务实现可以在业务仓，但以下内容必须进入本次联合发版清单。不能把
“通用仓不放业务内容”解释为业务适配不用交付。详细修复方案见
[BUSINESS_ADAPTER_REPAIR_PLAN.md](BUSINESS_ADAPTER_REPAIR_PLAN.md)。

| ID | 必须齐备的内容 | 责任边界 | 最小验收出口 |
| --- | --- | --- | --- |
| B01 | 版本化业务适配契约 | 核心定义契约；业务提供实现 | 包 ID/版本、兼容范围、工具/插件/模型/凭据名称、工作区和记忆映射齐全；不兼容或缺依赖时明确拒绝 |
| B02 | 业务身份与行为规则 | 通用骨架 + 业务叠加；实例组装 | SOUL/AGENTS 的来源与用途可追溯，实际输入模型的规则已核对；无冲突绝对指令；现场人工修改不被静默覆盖 |
| B03 | 业务技能与知识来源 | 业务仓/知识库 | 技能安装后能被发现并按预期触发；引用可追溯版本；没有把示例或过期副本装成生产真值 |
| B04 | 业务工具/MCP 及实际实现 | 业务服务；宿主负责注册授权 | 工具可发现且真返回授权业务数据；服务代码/工作目录/版本可确认；超时和后端失败不伪装空结果 |
| B05 | 业务任务闭环与质量标准 | 业务流程复用通用任务接口 | 选定代表性业务样本，验证查询→执行→结果→报告；含失败和边界样本；业务正确性由验收标准判定，不靠模型自述 |
| B06 | 业务记忆适配 | 业务术语/代际 + 核心存储召回 | 主体映射、嵌入后端/维度、知识更新策略明确；升级后真实业务样本仍可召回，不串身份或版本 |
| B07 | 外部环境与资源接入 | 实例管理员/业务运行平台 | 仓库、服务端点、设备/容器、文件权限和凭据引用按实际需要清点；只验证本业务依赖，不默认索取额外权限 |

业务层提供领域语义、工具与流程，不另造 Pool、交付主账或卡片发送者。
`agentcore/profile_overlay.py` 的现有资产采集/应用机制，不应被直接等同于
B01 所要求的完整兼容契约；后者仍需逐项证据。

## 5. 可选扩展：必须有状态，不要求默认开启

| ID | 扩展能力 | 如何避免成为隐含发版缺口 |
| --- | --- | --- |
| E01 | 动态招聘、团队包、直接追问成员、多阶段岗位编排 | 与基础岗位派工分开验收；未接生命周期驱动就写“不支持/关闭”，不能用登记成功冒充入职成功 |
| E02 | 夜间复盘与定时任务 | 声明作业、时区、预算、重试/重复抑制及权限；先手动验通；不默认自动合并、部署或重启 |
| E03 | 外部资料学习、技能蒸馏、记忆可塑性/跨库同步 | 分别说明输入来源、审查、晋升、撤销与消费者；未接线的库不宣称可用；不因存在测试自动启用 |
| E04 | 主动巡检、主动告警、自动修复 | 区分观察、建议、通知和执行；每步有开关与授权；没有自动执行就不宣称会自愈 |
| E05 | 本地模型辅助检索、FlowCoro 后端 | 标注依赖与降级行为；只有目标环境实测后才承诺性能收益；缺失可选后端不得静默变成通过 |
| E06 | 代码图谱、额外渲染/导出与执行器适配 | 说明是否随包、如何调用和验收；复用副本要有权威来源与版本，不把辅助工具视为运行主干 |

原生卡片备用实现不是需要同时开启的扩展。当前 HFC 唯一交互生产者约定不变，
任何未来替换都需单独迁移和验收，而不是为“齐全”运行两套发送者。

## 6. 每版怎么填

每个主表 ID 记录一行，可选项也必须明确是否纳入本版：

| 能力 ID | 本版承诺 | 实现证据 | 安装/配置证据 | 运行与功能证据 | 验收结论 | 负责人/阻断项 |
| --- | --- | --- | --- | --- | --- | --- |
| C01（示例） | 待确认 | 待填：提交及测试记录 | 待填：目标实例和配置摘要 | 待填：时间、场景、实际结果 | 待验收 | 待指定 |

结论只使用：**通过、失败、未验收、不适用**。不适用必须在范围冻结前说明原因；
可选能力另记“关闭/不支持”。通过必须指明证据覆盖的版本与目标实例，
不能把另一提交、另一 profile 或替身 transport 的结果挪来充数。

### 建议发版硬门槛

1. 冻结核心、业务适配、实例清单及外部依赖组合；每项有责任人。
2. 全部本版承诺项通过；关键场景跳过、未知或未验收均不算通过。
3. 串身份、权限绕过、未知副作用盲重放、凭据泄漏、数据破坏或回退失败，任一阻断发布。
4. 隔离环境通过新装、升级、幂等及失败回退；不能用源码单测替代。
5. 在明确授权的测试目标完成真实模型、卡片、连续消息、插话、附件及业务样本验收。
6. 生成版本绑定的发布说明：启用项、关闭项、限制、证据、备份、切换及回退步骤。

此清单不是新的自动化校验器。现有 `checks/real_link_acceptance.py` 部分场景
直接操作临时 Pool，不能据其名称认定真实 IM 插话或真实服务恢复已验通；
`checks/deployment_layered_audit.py` 也不能仅凭进程环境或日志没有报错证明完整功能。
复用这些检查的有效部分，缺口逐项补证，不再创建平行的健康/任务主账。

## 7. 当前不可直接打勾的重点

以下是阅读当前仓库与 readiness 文档后的提醒，不是本次重新执行的验收报告：

| 范围 | 已有基础 | 仍需补齐的证据 |
| --- | --- | --- |
| 后台与前台 | 持久队列、只读 runner、前台门禁与隔离恢复测试 | 目标宿主、真实模型/渠道、服务重启及可插话的完整链路 |
| 研发同事 | 岗位、登记、执行和验收接缝 | 可信执行边界及真实研发闭环；不得删除现有 containment 门禁来解锁 |
| 卡片与交付 | HFC 锁与自动契约，唯一生产者约定 | 对应构建的真实客户端逐场景验收及未知发送核对 |
| 记忆 | 存储、捕获、准入、召回及身份路由实现 | 真实模型质量、多身份反例、授权共享及目标环境启用 |
| 业务适配 | 身份合成、overlay 机制、业务清单与修复计划 | 版本化业务契约完整性、真实工具/业务样本和四态一致性 |
| 发布部署 | 打包、受管安装、候选与干净室测试机制 | 当前冻结输入的全部证据、正式干净发布物、目标安装及回退验收 |

**因此，这份表是“完整版还需要逐项交付什么”，不是“现在已经齐全”。**
