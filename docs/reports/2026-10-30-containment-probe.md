# 进程隔离取证：本机结果与未完成项

## 已复现的问题

在 WSL caixuf 上启动一个继承任务 token 的子进程，让它通过 exec 清空环境变量并继续运行。原来的 /proc 环境扫描返回空，sweep 却报告 quiescent=true 并生成证明编号；与此同时，子进程仍然活着。这个编号不能证明整次任务已经结束。只读不到其他用户进程、进程被 systemd 或 Docker 代为启动时，同样不能靠 token 扫描证明不存在残留。

本轮本机修改把 token 扫描结果标记为 token_scan，不再由它签发整次任务的完成证明。带队列 token 的同事执行因此会保守地返回失败或结果未知，不能直接用于生产；普通队列回执中的 attempt_quiescent 改为未知，并单独记录 token 扫描是否为空。仅有外部 launcher 自述 whole_attempt 仍不是独立证明，也不能作为已完成的隔离方案。

## 本机 systemd 实测

运行 checks/systemd_containment_probe.py，会创建一个随机命名的临时 user service，在其中启动主动 setsid 的子进程，确认子进程仍在该单元控制组后停止该单元。2026-10-30 在本机运行成功：停止单元后子进程不存在。脚本只对自己生成的单元操作，退出时尝试清理。

这只验证同一 systemd 单元中的普通进程，不证明 Docker daemon 创建的容器、另一个 systemd 单元、远程进程、文件系统副作用或网络请求都被隔离或撤销，也不证明其他机器有相同的 systemd 权限。该探针尚未接入任务执行、取消、重启恢复或生产。

## 后续必须完成

1. 设计并实现受信任的任务专属控制组，记录 boot ID、unit、调用实例及控制组身份，覆盖启动与崩溃恢复；不依赖执行器自己宣称已经清理。
2. 为 Docker 容器建立可核验的 attempt 所有权和存活检查，覆盖启动、删除、超时及守护进程不可用；控制组和容器两边都核验后才能解除占位。
3. 对不受该边界约束的网关托管任务，继续保持结果未知，不自动重试或宣称撤销。
4. 恢复流程必须在本机以清空 token、setsid、崩溃、重启和不可读状态等对抗场景实测，并接通实际同事链路。

## 本轮验证

本机修改后，sweep 的 quiescent 始终不再因 token 扫描为空而变成 true；是否扫到 token 单独用 token_scan_empty 表示。带队列 token 的同事 worker 在没有完整证明时保留失败或未知，不伪造结案证据。这个安全闸会影响现有同事功能，不能作为最终可用方案。

回归中，最后一次调整扫描返回字段前，完整套件 1635 项通过、30 项跳过；调整后隔离、同事、队列相关 78 项通过、2 项跳过。跳过项包括本机缺失的 FlowCoro 原生绑定与 Hermes 模块，不能算真实平台验证。

现有 evidence_id 接受受信任 launcher 自报 whole_attempt 字段只是接口约定，尚未独立核验该来源的控制组、实例与容器身份；测试替身能构造该字段不构成生产证明。必须完成真正的可信证明提供者与恢复流程后再启用或部署。

## 交接前安全收口

此前 worker 会先执行任务，再因无法证明隔离而返回失败；如果任务已产生副作用，这会诱发重复操作。现在带有效队列 token 的同事 worker 在没有接入可信隔离提供者时，在执行前直接拒绝。回归通过标记文件验证 runner 未被调用。没有 token 的兼容路径仍可能执行并返回无证明回执；外部 launcher 自述 whole_attempt 也没有独立核验。不要把这两个路径当作完整隔离。

本次收口后的相关回归 78 通过、2 跳过；FlowCoro 原生绑定及真实 Hermes 环境仍未验证。当前行为意味着队列派发的同事工作不可用，不可部署成成品。另有 pool 的 replay_safe 自动重派缺少隔离证明问题尚未修复，详见 stability-handover。
