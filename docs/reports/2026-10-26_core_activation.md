# 核心派工已接入常驻服务

本轮把持久队列、独立 FlowCoro worker、Hermes 工具和只读分析接成了运行链路。服务已启用，网关没有重启。这里的“通过”是机器实测，不等于用户已验收，也不等于所有消息平台已接通。

## 实际通过了什么

- 新 API 会话确实调用 durable_submit，而不是仅在回复中提到工具；先返回任务编号并结束本轮，实际耗时 17.111 秒，含工具发现与模型往返。
- 独立 worker 使用现场模型分析合成日志，产出报告和来源快照。durable_status 能在主会话返回中文摘要、引用与限制说明。
- 对已完成任务实际调用 durable_cancel，返回 request_accepted=false、already_terminal=true，没有伪称任务已停止。
- 为了确定后台任务尚未结束，使用只属于本次测试的受控暂停，另设 35 秒自动恢复看门狗。任务仍为 running 时，主会话 4.72 秒回答普通问题；恢复后任务完成。这证明 API 入口在该受控条件下可独立回复，不是业务负载压测。
- 独立服务主进程遭 SIGKILL 后由 systemd 重启，任务在新 attempt 完成，tries 从 1 变为 2，故障后 74.506 秒写出报告。故障注入命令因辅助进程信号报错而退出 1；日志确认主进程确实退出并重启，不能声称整组信号操作成功。
- 网关 PID 全程保持 3381565。三项测试任务的回执已本地确认，避免未来消息消费者误发测试结果；保留任务与报告。

## 修掉的实际问题

运行插件的解释器没有安装 agentcore 包。插件现在按管理员 engine_root 加载规范源码，不改全局 sys.path；任务不能选择执行器。成功回执新增有界中文摘要，避免只给报告路径。来源敏感内容检查只针对实际选送的行，仍校验路径和完整文件哈希；没有选送的行不会进入提示。取消终态任务的结果也已修正。

## 依赖与验证

FlowCoro 4.0.0 绑定按 worker 的 CPython 3.12 安装到持久目录，生产服务不依赖 /tmp 构建。上游提交 aaac885e673e01b6f21037a47930ef744668d26b；绑定 SHA-256 为 7397dcf967fa4b9e3ce6c2350d68aea28c0ba5dec00df792b2a943fcbedb9c4c。

完整 verify.sh：276 项测试通过，9 个 shell 语法检查通过，安装器 dry-run 通过。计数来自当时完整工作树，包含并行工作已有测试；本轮不提交其他人的改动。执行时临时测试目录使用本机 tmpfs，PYTHONPATH 包含真实原生绑定；这不是持久磁盘吞吐测试。

## 还没有通过的门

真实消息平台的人类业务案例、分析准确性与使用观感尚待验收；自动回填和同卡到终尚未接通。模型何时主动选择派工、提交后是否总能及时结束本轮，仍由模型和角色契约决定，没有强制终轮机制。引用检查只证明来源文字匹配，不能证明因果结论正确。

只读分析器不是任意代码沙箱。本轮没有实现自动记忆、记忆压缩或联网学习；没有对生产记忆做清理。完整功能收齐与 Docker 干净部署仍放在最后。
