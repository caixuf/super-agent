# 写 Mermaid 图的规范（让图自己说清话）

图的目标是**替读者省下逐字读**。以下每条都对应一类"图对了但没人看懂"：

## 1. 布局与连线

- **少交叉、汇聚收在末端**：多条边挤进同一个节点时，读者会把"汇聚"读成"环节之间的依赖"。
  能拆成两条独立路径（例如"卡片终稿"与"文本终稿"）就不要合并成一个出口节点。
- 一条**无标签**的直连边是最容易被误读的元素——要么删，要么给标签。
- `flowchart LR` 配 `subgraph` 分组（如"每轮组装"），比把角色平铺在一条线上好读得多。
- 节点文字**按语义断行**，用 `<br/>`：交给渲染器按字数硬断，会把 `同一张卡片 / 原地 patch`
  这类语义切碎并拉高节点。

## 2. 分色（2~3 个低饱和语义色，别做成彩虹）

全程灰阶的图要靠逐字读才能分清角色。用 `classDef` 给语义上色，且**同一文档内统一**：

```mermaid
flowchart LR
  A["入口"]:::user --> B["核心步骤"]:::core
  B --> C["缓存/记忆"]:::store
  classDef user  fill:#eef4ff,stroke:#0b5fff,color:#0b3fa8
  classDef core  fill:#ffffff,stroke:#94a3b8,color:#1c2024
  classDef store fill:#f3f5f8,stroke:#cbd5e1,color:#39404a
  classDef hot   fill:#fff8e6,stroke:#ead9a8,color:#6b5733
  classDef warn  fill:#f1f8f4,stroke:#a7d7c0,color:#2f6b52
```

分工建议：**蓝**=人/入口/交付，**白灰**=中性步骤，**浅灰蓝**=存储/记忆，**浅黄**=进行中/待定，
**浅绿**=受限角色（只读、叶子）。

## 3. 时序图（sequenceDiagram）

- `autonumber` 的序号圆点是全图对比度最高的元素，会反压消息文字：把
  `themeVariables.sequenceNumberColor` 调淡（渲染器默认已调成浅灰）。
- `Note` 用浅黄便签色（`noteBkgColor` / `noteBorderColor` / `noteTextColor`），别用深色块——
  浅色主题里一个深色块会抢走全部注意力。
- `loop` / `alt` 标签写**短条件**（`每 ~0.8 秒`），长句会伸出生命线外侧。
- 长消息标签会横向溢出，把它拆成两条或改成缩写。

## 4. 自检（渲染后必做）

1. 用 `scripts/verify_render.sh` 检查真实 SVG 数、渲染就绪、源码残留和布局；期望图数从源文取。
2. 把 PNG 当校样读一遍：有没有语义色缺失、连线交叉、节点贴边、文字糊成一团。
3. 图里出现的每个名词，正文里都应能读到解释；图是索引，不是全部内容。


## 5. 图也要讲人话

- 节点写角色和动作，例如“接收任务”“保存结果”，需要核对时才补代码名。
- 一张总览只放主要关系；超过读者一眼能分清的范围就拆成总览与局部解释。
- 图后的文字说明该看什么，用一个例子解释不熟悉的机制。
- 计划缺少真实日期就画阶段和依赖；并行任务如实并行，不为了好看而伪造先后顺序。
- SVG 数量正确不等于文字易读。渲染检查出现小字警告时，要看实际图片，必要时减少节点、缩短标签或拆图。
