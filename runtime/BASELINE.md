# 能力基线与无人值守档 —— 通用键名与地板值

**本文件只讲通用键**（换行业、换机器都适用的 Hermes 配置）；业务键（provider / MCP / 平台开关）
由业务叠加层给出，不在这里列。

## 1. 为什么单列一份

下面这些键不是"调参偏好"，而是**地板**：低于它，整类工作直接做不了 —— 长诊断链被中途截断、
并行只读取证退化成串行、派工深度变 0、无人值守时每步都在等人点确认。

而它们**全部住在现场 `config.yaml`（git 之外）**。两个后果：

- **clone 一个仓不会带走它们** → 新机器上是默认值（更小、更保守），机器人「能起来但变弱」；
- 它们**会被反复改小**，而没有人会记得改回来 → 必须由**巡检作业检测并回写**，不许靠人的记性。

## 2. 键名表（通用）

| 键 | 类型 | 地板值（建议） | 低于地板会怎样 |
| :--- | :--- | :--- | :--- |
| `agent.max_turns` | 整数 | ≥ 1000 | 长任务（证据 → 根因 → 补丁 → 验证）被中途截断；重跑代价远大于省下的 token |
| `delegation.max_iterations` | 整数 | ≥ 250（代码默认） | 子 agent 迭代不足，复杂子任务半途而废 |
| `delegation.max_concurrent_children` | 整数 | ≥ 8（关键路径按需 10） | 互相独立的只读取证退化成串行 |
| `delegation.max_spawn_depth` | 整数 | ≥ 3 | 只能派一层，跨阶段链路无法拆分 |
| `approvals.mode` | 枚举 | 无人值守档 = `off` | 每步都等人点确认 —— 无人值守直接停摆 |
| `approvals.timeout` | 秒 | ≥ 900 | 人工放行窗口太窄；**审批超时是沉默，不是同意** |
| `security.protected_instruction_files` | 布尔 | 保持默认 `true`；关它是**显式降级** | 关掉 = 移除提示注入的持久化防线（见 §4） |

现场值（上下文窗口 / 压缩阈值 / 并发预算）**在新机器上重测**，不要照搬旧机的数字。

## 3. 两条纪律

1. **守卫靠巡检，不靠记性。** 巡检作业读现场 `config.yaml`，与地板表比对；低于地板就**原子回写**
   （写临时文件 + `os.replace`），并告警。被反复改的东西一律做成自动守护 —— 只写在文档里等于没做。
2. **上限设得再高，也不许把长任务堵在会话槽位里。** 会话准入是每会话持久 FIFO（同一会话同一时刻一轮），
   所以 T2 长任务必须后台化（派工 / 建单 / 后台进程 + 看门狗），否则再高的上限也救不回"用户发一句等三分钟"。

## 4. 两个门不要混为一谈

| 门 | 管什么 | 打开/关闭的后果 |
| :--- | :--- | :--- |
| `approvals.mode` | 要不要**人工批准**每一次动手 | 设 `off` = 无人值守，但**不**解除指令文件写入门禁 |
| `security.protected_instruction_files` | 能不能**写指令类文件**（身份 / 项目契约 / 规则文件） | 默认 `true` 是提示注入的持久化防线；改 `false` 是**显式安全降级** |

两者**互不代偿**：`off` 审批档位拦不住写保护门，写保护开关也不会替你批准任何操作。
关掉写保护必须按降级处理：**留痕**（改了哪个键、为什么、复原命令）、纳入巡检基线守护，
并明确接受"提示注入拦网被移除"这一代价。复原：

```bash
hermes config set security.protected_instruction_files true
```

## 5. 怎么落地

```bash
# 显式开关，默认**不动**任何配置；会逐条打印将写入的键、值、以及复原命令
bash install/install.sh --profile <name> --apply-baseline

# 不想让安装器碰配置？把这条打印出来手工执行（`hermes config set KEY VAL` 是官方写入口，
# 千万不要手编 config.yaml —— 一个缩进就能把现场网关弄坏）
```

安装器**只**通过官方设置命令写这几个通用键，绝不整文件覆盖现场 `config.yaml`
（现场文件里内联着 provider / MCP 段与密钥，覆盖会静默冲掉它们）。
