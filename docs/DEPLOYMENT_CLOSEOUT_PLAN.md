# Super Agent 升级收尾与部署计划

基线：本机 WSL 的 `super-agent`，提交 `a24370c`（2026-10-29）。本文按“先恢复稳定可用，再逐项启用新能力”安排。它描述后续工作，不代表这些工作已经完成。本机测试使用 caixuf 和独立 profile；不在远端实例上做开发测试。测试消息由用户手动发送。

## 要交付什么

先交付一个可回退的升级：领域助手的正常对话、工具调用和长任务体验经验证后可用。新同事、共享记忆、夜间复盘各自单独验收、单独启用；没有通过的功能保持关闭或沿用旧链路。只有在确认业务需要并完成对应验收后，才切换生产路径。最终的一键部署和 Docker 干净室仍放在全部功能收尾之后。

## 1. 固定基线和部署清单

- 记录 Super Agent、Hermes、插件和 FlowCoro 实际版本，核对本机与目标实例的差异：启动方式、profile、启用插件、模型路由、记忆目录、消息渠道、外部依赖和凭据名称；不复制密钥到仓库或报告。
- 明确旧链路与新链路各由谁发送回复、谁持有任务，避免两套系统同时派工或回填。核查上游补丁是否与目标 Hermes 版本兼容。
- 在本机隔离环境重跑完整仓库回归，记录命令、通过/失败/跳过及其原因；保留最近一次运行中曾出现的归属异常作为待排查风险。真实发送测试不默认触发。
- 出口：有版本与配置差异表、完整测试报告及明确的启用清单；可选依赖缺失的测试算跳过，不算通过。

## 2. 优先完成长任务交互

- 将现有 `task-progress` 与目标 Hermes 版本接线，复用同一任务入口；覆盖接单、等待模型、执行工具、后台工作、完成和失败等能被证据支持的状态。没有事件时显示等待，不编造百分比。
- 在 caixuf 隔离 profile 验证：长任务中用户插话、同一会话连续消息、不同会话并行、进程重启与恢复；核对不串会话、不丢消息、不重复回复。复现和定位此前偶发的归属异常。
- 用户手动在测试号发起真实任务，检查同一进度消息的创建、编辑和最终结果；模拟编辑结果不明时应停止盲目重发。记录消息身份、时间和结果，附件单独验收。
- 出口：以上场景有逐项证据，正常聊天和工具调用没有回归；有问题时可关闭新进度插件回到旧路径。

## 3. 控制长会话退化

- 用隔离会话构造长输入和连续工具结果，记录压缩前后 token、耗时、压缩是否进入下一轮；验证压缩失败时状态明确、正常对话可继续。
- 核对技能按需加载、重复消息写入、记忆召回失败提示以及任务结果交付。至少复现旧实例中“上下文膨胀后接不住请求”的等价场景，并验证改动后的行为；不承诺仅凭升级解决全部模型质量问题。
- 出口：有基线和对比数据，连续多轮大输入后仍能正确回复；失败时能观察到原因，不把召回故障当成没有记忆。

## 4. 同事制度：完成真实执行后再启用

- 先确定真实 Hermes 任务由哪个进程执行、如何唯一标识一次任务，以及如何在完成、取消、超时和重启后证明工作及副作用已停止。环境变量令牌扫描只能提供局部证据，不能证明共享 Gateway 启动的进程或移除标记的进程已经停止；旧文档里更强的相关表述不能当作上线依据。
- 实现并接入可信的生命周期管理和成员创建/就绪组件；保持无法确认时拒绝派工或保留占用，不通过自动重试掩盖不确定状态。新旧派工及交付路径保持互斥。
- 本机先用模拟模型和真实 Gateway 验证恢复、去重、取消及身份绑定，再使用真实模型完成一条只读任务。随后用户手动在测试会话验证：主 Bot 授权招聘 → 派工 → 指明同事 → 收到有可信署名的结果 → 追问同事；记录结果与附件是否送达。
- 出口：任务及结果与发起会话一一对应，异常情况下不重复执行、不错误宣称完成；未达到时同事派工保持关闭，不阻塞单 Agent 对话功能的独立发布。

## 5. 记忆、模型路由和夜间复盘分别验收

- **共享记忆**：在隔离库接入真实成员身份和 Gateway 回合；建立小型评测集，检查新会话自动召回的命中与误命中、写入去重、矛盾处理、延迟和预算。共享长期记忆，成员会话历史保持隔离。未通过前不接生产记忆库。
- **main / flash**：核对 CCP 的逻辑别名、权限和超时；让 flash 先处理只读提取等适合的任务，主模型负责决策和核验。记录质量、成本与耗时；失败安全回退，避免把草稿当成已核实事实。
- **图文**：用架构介绍、概念讲解和计划三类样例检查何时触发、来源、可读性、渲染和附件送达；flash 草稿不等于可直接交付的文档。
- **夜间复盘**：先在隔离 profile 手动运行一次，再验证 01:00 调度、报告权限、负载检查与重复控制。默认只生成报告和隔离工作树，不自动合并、部署或重启。
- 出口：每项分别有配置、测试记录和开关；未完成的功能保持关闭，不声称全自动已经上线。

## 6. 部署与回滚

1. 部署前确认目标实例的空闲窗口，记录旧版本、插件状态、服务配置与回滚命令；备份相关配置和必要数据，并确认备份可读取。记忆库迁移或压缩单独制定恢复演练，不随普通升级执行。
2. 先在本机 caixuf 以隔离 profile 完整演练安装、启动、健康检查、普通聊天、长任务和回滚；记录需要重启或热加载的每项变更，不假设所有修改自动生效。
3. 完成本机门槛后，再针对远端实例实例核对版本和配置，在确认窗口中按功能开关逐项部署；用户手动发送测试消息，检查实际链路。不要同时启用两个派工或交付入口。
4. 部署后观察错误率、任务状态、进度消息、上下文规模和响应时间；出现串会话、重复副作用、结果丢失或持续不可用时，停用新路径并按已演练的方法回退，保留日志和任务记录。
5. 交付报告列出部署版本、启用和未启用功能、测试证据、已知限制、回滚方式，以及后续负责人。

## 最后阶段：可复现交付

全部预定功能收尾后，整理仓库安装器、插件和必要补丁，钉住 Hermes 等外部版本，提供不含密钥的凭据引导；在干净机器或隔离 profile 执行安装与冒烟，并在 Docker 干净环境逐项实测。Docker 环境与现场 GPU、网络和渠道能力的差异必须单列，不能把脚本通过当作所有真实业务均已验收。
