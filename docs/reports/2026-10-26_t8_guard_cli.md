## Contract

```
python3 -m agentcore.capability_guard_cli \
  --patrol-json <file|-> --queue-root <root> --profile <p> --scope <s> \
  [--webhook-url URL] [--token T] [--timeout SECONDS] \
  [--config-persisted|--no-config-persisted] \
  [--runtime-loaded|--no-runtime-loaded] \
  [--dry-run|--no-dry-run]
```

* `--dry-run` is the default (`BooleanOptionalAction`); `--no-dry-run` performs
  the durable write/send. Dry-run creates no queue directory, records no
  episode, and issues no HTTP request. It only parses the patrol JSON, derives
  the inspection, validates the webhook URL shape, and prints the message.
* Live mode constructs `AlertOutbox(queue_root)` and `WebhookSender(url, ...)`
  when a URL is present, then calls `run_guard(sender=...)`. Missing URL means
  `sender=None`: the event is recorded and remains pending.
* `--config-persisted` / `--runtime-loaded` refine the rendered preview only.
  Live mode exits 2 if an override contradicts the inspector-derived inspection,
  so the durable payload never records a fact the patrol did not report.
* The token is never printed and never stored in the event; the summary only
  reports `webhook_configured`.
* Output is one JSON object on stdout (stderr for errors), including
  `status`, `drifted`, `message`, `delivery`, `pending_count`, `exit_code`.

## Exit codes

| code | meaning |
|---|---|
| 0 | quiet / deduplicated / delivered; also any valid dry-run preview |
| 2 | malformed input: unreadable or invalid JSON, non-object patrol, invalid patrol field types, invalid webhook config, live override contradiction |
| 3 | no delivery target configured (no URL) or the outbox root is unavailable |
| 4 | delivery failed or outcome unknown; the event stays pending for lease-based retry |

Deliberate: a dry run returns 0 even when a drift would be un-deliverable
without `--webhook-url`, because dry run performs no delivery attempt and is
a validation/preview operation. Live mode is where 3/4 apply.

* dry run is default, renders the alert, sends nothing, creates no queue root;
* dry-run quiet patrol renders no message and exits 0;

* invalid webhook URL -> exit 2;
* `--patrol-json -` reads stdin.

## Known gaps / host decisions

1. **No inspector call.** The CLI consumes a pre-computed patrol JSON. The host
   must serialize `ops_patrol.inspect_capability_baseline` itself, exactly as
   `capability_guard` documents. This keeps detection authoritative.
2. **No target policy.** No environment variables and no host config are read;
   URL/token must be explicit. Default remains off.
3. **Override scope.** `--config-persisted`/`--runtime-loaded` cannot rewrite a
   durable event; live contradictions are refused instead of silently ignored.
4. **Deduplication is per `(profile, scope)` episode**, inherited from the
   outbox. Repeated drift after a healthy observation creates a new generation.
5. **Retry is lease-based**, driven by later CLI runs; the CLI is a single
   observation pass and does not loop. A failed send can be re-attempted by
   rerunning with the same queue root.
6. **No scheduling/daemon wiring.** Cron/systemd ownership stays with the host.
